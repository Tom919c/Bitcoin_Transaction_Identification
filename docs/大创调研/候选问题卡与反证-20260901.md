## 1. 本轮实质变化

- M不能以“首次评价聚类可靠性”“增加受控钱包实验”或“输出多种聚类指标”为创新：这些都有明确前作。剩余问题必须落到现有防护对特定有效协作协议的失败及跨实现权衡。
- N2收敛为付款／找零角色和经济付款额测量。其预测对象可以与M的地址对／簇区分；若最终只测M模型的稳定性，则仍应并入M，不占独立替代名额。
- N3的来源复制检测、时间变化和真值融合已有直接方法。候选只保留可审计Bitcoin声明修订对固定下游结论的影响；不能借“证据图”名称宣称算法原创。
- 25条发现记录完成摘要范围初筛，均保留深入核验；两项原拟排除的银行AML研究经负责人复核改为方法参照。初筛不等于同意摘要的标签、数值或部署主张。

## 2. M：协作交易下的地址关联可靠性

| 字段 | 当前定义与证据边界 |
|---|---|
| 问题 | 现有共同输入聚类、CoinJoin／UIH过滤与保守约束，对协议有效的协作式市场结算，是否还存在跨实现可重现的错误关联？如有，能否在相同正确关联保留水平下减少误合并？ |
| 使用场景／单位 | 交易图分析者审查某个地址对为何被归入同一簇；评价地址对、簇及独立钱包轨迹，不把交易检测率当成聚类正确率 |
| 真值 | 独立记录的逻辑签名权限域。协议角色、签名标志和地址类型不自动等于不同自然人。多签／共享控制须单列，不能强制单标签 |
| 观察输入 | 已允许的链上交易、前序输出和截止时刻以前的历史。钱包日志、隐藏权限和PSBT私有协调信息只供评价，不给检测器 |
| 最近邻 | M01–M04及旧方向重评的BIP78、UIH、Möser、CoinJoin规则；没有完整原文支持的规则不得擅自简化为弱基线 |
| 剩余假设 | 具体结算族在上述强防护后仍有非平凡失败；防护增量不是识别自己生成的模板或拒绝全部关联。这两点尚未实验支持 |
| 数据路线 | 官方规范／源码→完整工件→协议与签名校验→独立权限记录→实现／钱包轨迹留出。公开SDK仅提供构造流程时不能填“工件已就绪”；受控构造检查在用户确认后的协议内执行 |
| 强基线 | 共同输入规则、适用CoinJoin规则、各UIH变体、拒绝含ANYONECANPAY交易的粗过滤、Möser式保守约束、不合并任何地址；最后一项是退化参照，不是期望产品 |
| 判别实验 | 固定正常找零／批付、自成交及多方协作条件；以实现和钱包轨迹留出。比较错误合并—正确关联保留曲线、簇分裂及未决比例；禁止随机拆同模板制造泛化 |
| 停止条件 | 仅重现已知PayJoin反例；粗过滤同等或更优；提升只来自模板泄漏；真值不能独立；所有收益由停止关联获得 |
| 理论卡 | 对观测交易O，若多个权限分配W产生相同O，则仅凭O不能唯一恢复W。这是已知不可识别性边界，不是新定理。尚无通过证明和最近邻审查的新理论 |
| 作品价值与边界 | 可展示原始证据、允许的关联、未决关系和误合并传播，并提供真实对照。受控结果不证明主网误合并比例，不解封旧CP-13，不对真实主体作违法判断 |

当前状态：值得继续比较的条件性问题，尚未证明创新增量。它有较具体的机制，不因此自动胜过其他候选。

## 3. N2：协议有效变化下的付款额与找零识别

| 字段 | 当前定义与证据边界 |
|---|---|
| 问题 | 当同一明确付款意图采用不同有效选币、找零脚本或输出顺序时，现有付款／找零识别与经济付款额估计会出现多大误差？误差是否由钱包实现特征替代付款语义造成，能否在留出钱包上改善？ |
| 使用场景／单位 | 面向链上经济活动测量和交易解释；单位为输出角色与交易／付款意图级净付款额。它不直接分类实体、违法交易或洗钱 |
| 真值 | 构造前固定收款对象及付款额，保存生成日志、输入控制域、输出归属和费用约定；每个变体单独校验。日志只定义受控意图，不证明现实经济交易发生 |
| 保持条件 | 普通付款变体保留收款脚本／金额与找零控制域。若引入PayJoin，接收方可加入自己的输入，输出额不再等于净收款；必须预先限定协议子集并用独立权限账目计算净转移，不能把每个输出金额机械保持作为通用条件 |
| 观察输入 | 只给交易和允许的历史。不得把“哪个脚本是接收方”“哪个输出受发送方控制”等隐藏日志用于预测基线。输出置换前后用评价侧对应关系核对，不把新txid当新独立意图 |
| 最近邻 | N201 Cole等TIM直接研究经济交易量／找零；N202 Möser研究找零；N203 BIP78明确破坏共同输入、脚本和整数额启发式；N204 Zhang已有Elliptic图扰动，但该节不证明有效UTXO反事实 |
| 剩余假设 | 留出钱包上的错误与构造选择存在稳定关系，并有超出已知“末尾输出是找零”反例的增量；目前没有实测证据。换序造成规则失败本身并不新颖 |
| 强基线 | TIM完整规则链、Möser单规则／投票／随机森林、适用的找零规则；表观输出总额只作粗参照。禁止把可见字段和隐藏角色混合成“完美不变量基线” |
| 判别实验 | 独立付款意图下产生合规变体；开发／评价按钱包实现和意图分组。报告角色误差、净付款额绝对误差、覆盖与拒判，以及变体配对翻转；稳定但总错的预测不算稳健 |
| 停止条件 | 无法明确净付款及角色真值；有效变化实际上改变了目标；只有已知规则反例或普通数据增强；效果只在同钱包模板上成立；简单强基线消除剩余差异 |
| 理论卡 | 不可区分的交易可对应不同意图，普适无误差经济解释不成立；当前只是边界，不是新理论。新不变性必须指定允许变换、目标和输入，不能用真值定义输入再证明正确 |
| 作品价值与边界 | 演示同一付款意图的不同有效交易及估计偏差，提供方法对照和失败解释；不能把受控净付款额推广为全网真实经济交易量 |

当前状态：问题定义可以独立于M，但创新仍待最近邻和判别实验。此前讨论将TIM误称为“Lammers 2022”；一手机构全文确认作者为Cole、Dyhrberg、Foley、Svec。书目信息现已纠正，不引用其摘要中的比例作为本项目效果。

## 4. N3：标签声明修订与来源依赖的下游影响

| 字段 | 当前定义与证据边界 |
|---|---|
| 问题 | 对可恢复版本的Bitcoin地址声明，来源同根与修订信息是否有助于识别哪些固定下游结论会失去依据或发生改变，且优于简单去重、最新版本和已有动态来源融合？ |
| 使用场景／单位 | 审计员复核标签支持的覆盖统计、关联说明或预先固定的候选排序。基本单位为“链上对象、属性语义、来源版本”，另记明确引用／复制关系 |
| 真值层次 | 版本存在和实际修订、明确引用边、固定流水线重放结果可以分别核验；这些都不等于现实归属或违法性真值。owner=服务使用者与owner=密钥控制方不能混为同一属性 |
| 时间与独立性 | 当时任务只能看当时已公开版本；后续版本用于检验修订事件，不能进入预测输入。引用、镜像、同源转载不算独立支持；文本相似本身不是复制方向真值 |
| 最近邻 | N301 Dong已有动态复制和真值生命周期；N302 Helping Hands已有来源流程及下游效用评价；N303 TagZilla覆盖逐IoC文本标签；Leng2026和APT to Disagree全文缺口仍保留 |
| 剩余假设 | 可合法恢复足够版本及根依据；实质修订会改变非平凡下游结论；依赖建模比简单根去重有用。尚未取得满足这些条件的Bitcoin语料 |
| 数据路线 | 先审计公开TagPack等真实版本历史，再区分添加、更正、删除、格式变化及上游失联；删除不自动视为标签错误或撤回。根证据不可恢复的条目只能进入未知类别 |
| 强基线 | URL／原始声明去重、最新版本、共同根计一次、多数票、静态及动态copy-aware融合、随机审计与不建依赖的完整重放 |
| 判别实验 | 第一阶段只检查真实修订是否造成下游差异及简单去重能否解决；该效应成立后，才能另行提出预测修订／审计排序任务。时间和source-family留出；不把机械重放等同于纠正事实 |
| 停止条件 | 只能自造来源网络；根边由模型自标后再自测；实质更正不足以评价；只有字段格式差异；下游几乎不变；已有方法或简单去重消除增量 |
| 理论卡 | 动态源依赖、HMM、时间真值融合均已有。依赖图可达性和撤回传播本身不是新定理；目前只支持待验证的实证／评测路线 |
| 作品价值与边界 | 可展示某个统计或说明在来源修订前后的依据；不自动裁定举报真假，不把撤回网页解释为无罪或有罪事实 |

当前状态：可独立于M/N2，但数据和最近邻缺口更明显；这不是工作量判定，也不证明该方向永远不可研究。应先做真实版本证据审计，不能直接搭建LLM报告系统。
