## 3. 大创阶段的决策流程

1. **规则与范围核验**：区分结题、立项层级遴选、校内专项奖励、省年会、全国年会及其他竞赛；核对原申报书、完成标准和可用资源。
2. **问题与作品比较**：研究真实使用场景、已有系统、代表性获奖作品和相关技术文献；形成约8–12个候选，比较问题价值、创新增量、证据、评价有效性、展示性和失败条件，暂不比较开发工作量。获奖案例只说明已有作品形式，不能证明某个技术或包装导致获奖。
3. **用户确认主问题后冻结验收协议**：一个主方向、两个替代和保底交付；明确数据、任务、指标、基线、时间信息边界、演示验收条件及停止条件。不得将方向讨论直接当作模型开发许可。
4. **低成本验证后实施**：先复用现有资源验证核心创新，再决定是否扩大实验；最终形成可信功能、实验对照、失败案例、过程记录、结题论文和答辩材料。
5. **年会增量准备**：在结题成果上深化，分别核验2027年的立项资格、推荐通道、学生身份、材料和名额；不为未确认的年会要求牺牲十月交付。

两条文献检索链仍保留：Undermind用于学术深检和组织，独立官方论文/数据/代码检索用于核验和反证。Zotero用于经过核验的核心文献。当前是官方规则核验，不能把政策网页数当成学术文献阅读量，也不声称已经完成此前147篇初筛、60篇来源核验或30篇全文阅读的要求。

## 11. 直接撞车检查后的条件性主推荐

负责人继续核验后发现，Payjoin组织的公开`tx-indexer`已经包含协作交易仿真、钱包权限与付款义务真值、共同输入／找零启发式、钱包指纹和输入输出金额分区；Gavenda等ESORICS 2025论文又已形式化带费用、实现限制及钱包行为的CoinJoin输入输出映射，并用仿真真实映射验证。因此，N2停止作为独立方向，M降为需要证明剩余误合并缺口的替代方向。这个变化来自直接最近邻，而非开发工作量。

新的条件性主推荐是 **“面向比特币调查文本的链上原子事实核验与可重放证据系统”**：只核验固定区块快照可以判定的交易存在、确认信息、输入引用、输出脚本／金额等原子陈述，输出“链上支持／链上矛盾／证据范围不足”及可由独立程序重放的证据证书。它不判断地址控制者、举报真假、犯罪或现实损失。RiskTagger已经覆盖事件材料抽取、资金追踪和报告生成，vChain已经覆盖区块链查询完整性证明，因此本项目的增量必须落在Bitcoin陈述语义、证据边界、可重放验证和专门基准，不能以LLM或Merkle证明本身作为创新。

E仍须先过数据门：来源许可明确、真实文本中可联合核验的链上锚点足够、双人标注可靠、规则基线没有使任务饱和。任一条件失败即停止主张并回退M，不用合成文本制造高分。旧研究账目经逐键审计，147条发现池中当前只有13条可安全复用为带本地章节／表格定位的来源；此前60篇来源核验、30篇全文阅读目标尚未完成。

完整来源、裁决、研究问题、交付形态和停止条件见[候选问题卡第11节](候选问题卡与反证-20260901.md)。用户确认该主问题后才进入协议冻结和数据门；当前没有恢复环境安装、训练或系统开发。

## 12. 数据门与Payjoin再次撞车后的当前状态

第11节的E条件性主推荐现已暂停。Ransomwhere固定Zenodo快照虽许可明确且含11,178个地址和18,890个唯一交易哈希，但已核字段没有原始报告文本、附件或证据链接，不能建立“从调查文本抽取并核验陈述”的独立基准。网页允许提交公开报告，不等于已有可再分发的固定文本语料；在找到至少50份许可明确、可下载并同时含文本、报告标识和明确链上锚点的样本前，不用合成文本或自生成标签补缺。

Payjoin比E更容易获得受控权限真值和有效交易，但宽泛M也不能直接晋级。Payjoin项目方2026年文章已经用钱包指纹、输入输出分区及前后交易证据分析真实Payjoin；`rust-payjoin`议题#1597又已比较六种集成并提出一致性策略；`tx-indexer`已经提供协作交易真值、启发式、分区和隐私指标。因而“发现跨钱包泄漏”“统一`nSequence`”或“做一个协作交易仿真评测”都不足以成为本项目创新。

目前只保留窄候选M'：在预注册的多属性链上指纹策略下，预广播一致性检查能否在**留出钱包或留出实现**上降低输入所有权分区的可恢复性，同时不造成过多无谓拒绝且不破坏协议有效性。它必须比较无检查、仅规范化`nSequence`和仅拒绝三类强基线，并使用独立权限真值；若只复现Cake Wallet已知缺陷、收益只出现在同源实现、简单规则等价、或隐私改善只是增加拒绝率，立即停止创新主张。

当前比较结论是：E的想法上限较高但数据门失败；Payjoin的可执行性较强但创新空间已大幅缩小。两者都未冻结，不能把E失败自动解释成Payjoin通过。Zotero中的旧版RiskTagger重复条目`22L6YX2Y`按用户要求保留，仅从统计中排除，不再安排删除。

## 13. 实体隔离救援筛查与新一轮淘汰

Payjoin的窄候选M'已完成组件级反方审查。`rust-payjoin`议题继续把跨实现差异扩展到relay轮询、重试、密钥获取、`nLockTime`等维度；项目方文章和`tx-indexer`又已覆盖多属性指纹、所有权分区、仿真真值及隐私指标。只剩“留出实现上的隐私收益—有效接受率曲线”这一联合评测缺口，作为高质量大创主创新仍过于增量。因此Payjoin关闭主线资格，仅保留协议一致性检查器和固定测试向量作为工程保底。

随后按大创标准重新检查“面向未见服务实体的可信分类评测”。Lin 2019全文确认地址级与实体级是两套独立十折任务，没有测试地址分类器面对未见实体；Zola 2022全文确认约1600万地址采用50/50分层随机地址切分，没有实体隔离。这说明问题信号真实，但普通`GroupKFold`本身不是创新，必须先证明MBAL公开工件支持跨链`source × entity`机制研究。

数据门实际失败。Kaggle官方API固定版本1为CC0，总大小4,788,090,644字节；主表`dataset_10m_ads.csv`为850,176,864字节，SHA-256为`0DC4C04A2994AF6AA9CC6F3216B252B5BFD315D3EA8042A05FFACDD070B52A57`。两个独立解析器一致得到1000万行、413个非空实体名；其中Bitcoin为1,808,605行、228,536条具名地址、172个实体，Ethereum为6,346,154行、3,217,937条具名地址、322个实体。这与论文摘要所述933个实体及四条链存在工件版本或统计口径差异，不能静默混用。

更决定性的回连审计使用论文公开Bitcoin训练、测试文件，哈希分别为`0AB3F7570FAF534DAC03C355603C3CFF1766AC913217304CFF00D845E2610C54`和`5C729E537669F74A4DD79F491781EFB5913424F996F921E49B7884C9CF1E4745`。913,378个实验地址中只有3,377个能回到主表；测试集只有246个地址有实体名，全部来自训练中已见的13个CEX实体，按训练实体名查表的测试准确率为1.0。该结果是身份捷径证据，却没有覆盖多类别未见实体评测所需真值。故M5按预先硬门停止，不能把它包装成当前最优方向。

Ransomwhere也不能救援“报告延迟感知的早期发现”。Zenodo v1.1.0文件SHA-256为`5C939F3F0D390813F78E649CDD5CD50DCAC6AC286E8C9BA52206B273F761082D`；11,178条记录只有31个`createdAt`日期，7,205条集中在2021-07-15，前五个日期覆盖10,953条。8,240个有交易的地址中，8,233个的全部记录交易发生在`createdAt`之前，首笔交易到创建日中位间隔约1,903天。结合原论文说明的大批历史数据导入，`createdAt`只能视为入库时间，不能解释为逐地址发现或报告公开时间。

当前没有冻结的新主方向。多观察点mempool仍具有较高问题上限，但公开artifact缺预测时手续费、交易体和冲突状态；UTXO预测缓存已有2021、2022、2025及2026直接前作，且Bitcoin Core 2026已合并原生并行prevout预取，因此U1停止主线资格。下一轮新增两个候选：跨Bitcoin Core版本／策略／状态的交易与package接纳差异测试P2，以及严格按时可见的延迟标签找零识别C1。继续核对官方测试后发现，P2的核心API、RBF/TRUC状态和结果一致性已有直接功能测试，故降为benchmark／工具候选；C1升为条件性首位，M1为第二替代。详细证据和硬门见候选卡第14节；用户尚未确认，不能把条件性排序写成最终定题。

## 14. 新候选轮：从模型标签转向可执行真值

P2的对象是同一笔交易或交易包在固定Bitcoin Core版本、策略配置和内存池状态下的接纳结果。输出不是“非法／合法”，而是可重放的接纳矩阵、差异归因和最小反例。官方议题#32160已经公开`testmempoolaccept`与真实package提交的差异；进一步审计发现`rpc_packages.py`已经比较两个接口并断言结果一致性，`mempool_package_rbf.py`和`mempool_truc.py`覆盖关键状态，`mempool_compatibility.py`处理跨版本mempool文件。扩大矩阵或增加界面不足以构成研究创新，P2仅在发现现有测试和文档都无法解释的稳定语义差异时才可能重新晋级。

C1重新利用找零识别问题，但把信息截止时间当作任务本身。Möser与Narayanan的公开数据只含`txhash,change_output_idx`；本轮通过Google Drive区间请求核验了文件头，未发现揭示交易或揭示高度。原论文采用静态随机切分，并允许使用输出后续花费交易的特征，没有报告标签揭示延迟、右删失或按时可见训练。C1只有在能从全链重建最早揭示高度、明确多输入启发式的失效边界并形成删失感知方法时才成立；后续花费关系不能被描述成现实主体身份真值。

M1的公开16观察点artifact经官方README复核，仅含交易哈希和各观察点首次时间戳，许可为CC BY-NC 4.0。ZeroMQ只能通知进入本地mempool的交易及增删事件；Bitcoin Core USDT的`net:inbound_message`可记录P2P消息和peer信息，二者组合说明重新采集技术上可行，但现有artifact无法恢复原始交易、手续费、package／冲突和本地拒绝状态。M1在取得多个地理与网络独立节点的完整预测时记录前不进入模型实验。

独立反方在加入官方功能测试证据后给出的当前处置为：C1做条件性主候选，M1做第二候选，P2降为benchmark／工具保底，Payjoin保留工程保底。共同禁止把策略差异称为共识漏洞、把后续花费称为实体身份、或把观察点缺席直接解释为拒绝。下一步先冻结C1的标签语义、最早揭示高度与右删失数据门；通过后再提交用户确认。

C1的最小公开链重放已完成。原论文明确剔除了交易发生时已经揭示找零的样本；前8条CSV记录全部能查到标签输出的后续花费，首次花费延迟为0至6070个区块。只有4条直接与目标原输入脚本共同花费，另4条需要追踪中间聚类合并；还有1条发生在同一区块内。因此完整协议必须按块高和块内顺序重建多输入连通的最早揭示时刻，不能把首次花费高度直接当标签时间。这只证明数据链原则上可重建，不证明启发式标签正确。

Gate 2当前提交包为：**主方向C1；替代M1与P2 benchmark；fallback Payjoin。** 用户确认C1后再冻结Gate 3A；未确认前不训练模型。

## 15. 2026-09-04正式申报书适配后的建议主方向

正式申报书、官方构图源码、当前252M数据库和最近邻全文核验完成后，Gate 2建议已变化：主方向建议为 **“面向比特币实体识别的严格按时可见构图与可信GNN评测”**。C1降为其中的未来关系揭示机制，Payjoin保留工程保底。

理由是官方流水线先用全期交易形成最终地址cluster，再用最终alias构造实体图；当前本地库只保留最终节点和聚合边，历史union信息已经丢失。若项目声称历史时点或未来时期识别，节点身份本身可能使用未来合并信息。已有最近邻分别研究聚类误差或交易级时间泄漏，尚未发现完整覆盖这一实体级问题的工作。

该建议尚待用户确认。确认后先重建小窗口union日志并做无模型数据门；只有观察到稳定、实质的跨时合并与评测影响，才进入完整GNN实验。详见[正式申报书适配审计](原立项适配审计-20260901.md)与[选题验证计划第11节](选题验证计划-20260901.md)。
