## 5. 正式使用约束

1. Gate 3A v1.0 与 S0 Go 之前，不向 Kaggle 提交模型训练或效果评测。
2. 每个远端任务必须默认 private；Internet 默认关闭，只有冻结输入确需访问公开源且已通过许可/隐私审计时才逐任务开启。
3. 不上传数据库连接串、私有标签、受限数据、身份信息、未发表正文或测试集结果。AWS 50 GiB 候选前缀不得因已有 Kaggle 通道而跳过许可、不可变快照和完整性硬门。
4. 每次提交前固定代码 commit、metadata、输入对象身份与 hash、协议版本、seed、资源和停止线；输出必须包含脚本/配置 hash、环境、状态和失败原因。
5. 单次工作量须在 12 小时内完成并留有余量；超过预算的流程拆成可校验 checkpoint，但不得用拆分规避预注册停止规则。
6. `/kaggle/working` 只保存必要的不可变结果、checkpoint 和 manifest；大数据应按许可允许的冻结源挂载或分块读取，不能依赖临时 scratch 作为唯一副本。
7. 训练、验证、阈值选择和校准仅使用协议允许的数据。测试集仍按 test-once 规则管理，Kaggle 不能成为绕过测试纪律的第二环境。
8. 远端运行结束后回收日志、配置、原始预测/结果与环境信息，核验 hash，再更新实验登记和决策日志。失败、配额不足和负结果同样保留。
