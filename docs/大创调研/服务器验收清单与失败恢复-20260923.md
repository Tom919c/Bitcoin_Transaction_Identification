## 3. 通过判据

分两组，**两组都通过才算验收通过**。哈希一致只证明"字节相同"，不自动等于"可用"，因此必须分别检查。

**A. 正确（字节一致）**

步骤 1 三个计数与字节数精确匹配；`verify_dataset_transfer.py` 的 `correct::*` 全部通过——`correct::transactions_vs_byte_freeze` 的 `ok=1890`、`missing=0`、`hash_mismatch=0`、`size_mismatch=0`；`correct::blocks_vs_local_manifest` 与 `correct::tx_sidecars_vs_local_manifest` 的 `missing=0`、`mismatched=0`；`correct::state_db_hash` 与 `correct::semantic_state` 的 `match=true`。

**B. 可用（能被消费）**

`usable::quick_check` 为 `ok`；`usable::counters` 的 `match=true` 且 `height_match=true`（三表行数与 `metadata.last_committed_height` 等于冻结 extractor summary）；`usable::parquet_summary` 的 `opened == sampled`。

最后 `acceptance` 必须为 `PASS`、`failed_checks` 为空。另需四脚本哈希全部匹配、`git rev-parse HEAD` 与本地一致。任何一项不成立即验收失败，按下节恢复。

## 3.1 单副本裁决

用户 2026-09-24 明确：只保留一份副本即可，服务器数据正确且可用即满足要求。因此验收不再以"存在第二份可恢复副本"为前置，但 **A、B 两组判据都必须通过**，且验收记录须保留完整输出，以便日后即使副本损坏也能判断哪些对象需要重取与重验。

## 3.2 执行时机（2026-09-24 实测补充）

**正式验收必须在全部传输结束、且确认没有写入进程时执行。** 传输进行中，正在被 `tar` 写入的文件会出现瞬态 size 不符（2026-09-24 02:25 的中间检查观察到 2 个），这属于在途状态而非损坏。中间检查的 `acceptance` 结果不具判定力，只能用于观察已完成部分的正确性与可用性。执行前先确认：`pgrep -af "send_dataset|send_state_db"` 为空，且各目录文件计数已稳定。

## 4. 失败恢复步骤

| 失败模式 | 现象 | 恢复动作 |
| --- | --- | --- |
| 传输中断（VPN 断线） | 日志出现 `Broken pipe` | 重新执行 `send_state_db.sh` 或 `send_dataset.sh`，按进度文件从断点续传；脚本内已含每单元 6 次重试 |
| 后台任务沙箱拒绝 `~/.ssh` | `ssh: Could not resolve hostname a100_chenquan` + 沙箱拒绝读取 `C:\Users\chenquan\.ssh` | 在沙箱设置中把 `C:\Users\chenquan\.ssh`（含 `.ssh\config`）加入后台白名单；改完无需重启应用 |
| 单个 transaction 对象哈希不符 | 校验器报 `hash_mismatch` 并给出 `cache_identity` | 先从 S3 重取该对象并比对 byte freeze；若 S3 也不符，说明公开桶内容已变，**保留本机冻结副本、不得用服务器副本替换**，并在验收记录中标注该对象 |
| `s0_union_v1_1.sqlite` 哈希不符 | 传输脚本报 `SHA256_MISMATCH` | 删除服务器副本，清空 `s0_state.pieces` 后重传；或按 512 MiB 分片只重发可疑分片 |
| 磁盘不足 | 写入报错 | 先查 `/workspace/chenquan` 余量；本机侧余量低于 20 GiB 时不得新增大文件 |
| 校验通过但版本不一致 | HEAD 与本地不同 | 用 `git bundle` 重新同步后再验收，不要在校验记录里混用两个版本 |

## 5. 验收记录必须包含

执行日期与执行人、`git rev-parse HEAD`、四脚本哈希、上述全部对象哈希、`verify_dataset_transfer.py` 的完整输出、环境登记（Python/sqlite/uv/pyarrow 版本、GPU 名称与驱动、核数与内存）、以及任何未通过项及其处置。记录落盘后写入 `experiments/experiment_registry.csv`。
