# 三个优先大创方向：给计算机本科生的通俗说明

日期：2026-09-04

状态：Gate 2推荐稿。方向尚未由用户确认，创新效果尚未通过实验验证。

## 先说明一个共同边界

现有数据中的`0–10`是交易所、个人、矿池、赌博服务等**实体类型**，不是“合法／非法”标签；`-1`只是没有标签。三个方向都不能把实体类型分类包装成犯罪识别。项目可以继续沿用原题名，但正文应写成“比特币实体识别、证据可靠性与审查辅助”。

## 推荐顺序

| 顺序 | 方向 | 一句话说明 | 当前判断 |
|---|---|---|---|
| 1 | 严格按时可见的实体图与可信GNN评测 | 防止模型在分析过去时偷偷使用未来才形成的地址合并关系 | 最推荐，最贴合申报书 |
| 2 | 延迟揭示标签下的找零关联识别 | 标签可能很久以后才出现，研究如何公平训练和评价 | 有研究价值，可作为方向1的子课题 |
| 3 | 多观察点内存池分歧与结果校准 | 多个Bitcoin节点看到的待确认交易不同，研究预测结果到底有多可靠 | 上限高，但必须重新采集完整数据 |

## 方向一：严格按时可见的实体图与可信GNN评测

### 通俗理解

假设学校在六月才知道“小王”和“王同学”其实是同一个人，却把这个六月得到的信息放回一月份的名单里，再声称一月份就能识别这个人。这就是“未来信息回填过去”。

比特币数据也可能出现类似问题：一批地址在早期看起来互不相关，后来因为共同参与一笔交易才被聚成同一个实体。如果我们用最终聚类结果表示整个历史，早期图中的节点身份就可能包含未来信息。

### 要做什么

1. 按区块顺序重新读取Bitcoin交易。
2. 每次两个地址被启发式规则合并时，记录合并时间、所用规则和过滤版本。
3. 在多个截止时点分别生成“当时能够知道的实体图”。
4. 将这些图与“看完整段历史后得到的最终实体图”逐一对照。
5. 在完全相同的地址和标签范围内，比较逻辑回归、树模型、MLP、GraphSAGE、GAT等模型。
6. 检查节点数量、边结构、标签冲突、模型排名、置信度和拒判情况改变了多少。
7. 做一个可视化系统，让答辩老师看到某个实体怎样因为未来交易而发生合并，以及模型判断如何随时间改变。

### 解决什么问题

它解决的不是“再设计一个更复杂的GNN”，而是回答一个更基础的问题：**原来的图和评测方式是否公平？模型成绩是否使用了部署时不可能获得的信息？**

如果这个问题不先解决，即使模型分数很高，也可能只是在利用未来信息或身份捷径。这个方向能直接提高原项目结论的可信度。

### 已有研究做到哪里

- [原数据论文](https://doi.org/10.1038/s41597-025-04684-8)构建了约2.52亿个最终实体节点，并使用随机节点切分评价GNN，但没有保存每次地址合并的时间，也没有做严格的历史分区评测。
- [官方构图代码](https://github.com/hugoschnoering2/BTCGraphConstruction/blob/3becbc44a951abbe1e85d374a66340a639059d1c/steps/populate_alias.py)按区块累计Union-Find合并，最后才写入唯一的`address -> alias`结果；[实体边代码](https://github.com/hugoschnoering2/BTCGraphConstruction/blob/3becbc44a951abbe1e85d374a66340a639059d1c/features/cluster_transaction_edges.py)再使用这张最终映射构图。
- [Müller等2026](https://arxiv.org/abs/2607.07414)证明常用多输入聚类并非可靠真值，但研究的是静态快照，没有研究下游GNN。
- [Maganti 2026](https://doi.org/10.48550/arXiv.2604.19514)研究了交易节点图的时间泄漏，但没有地址聚类和实体节点。

当前检索没有发现把“历史地址分区、最终分区、实体类型分类和GNN评测”完整连接起来的等价工作。这只说明方向值得验证，不能写成已经证明“全球首次”。

### 创新点在哪里

1. **让地址聚类带时间和来源。** 不只保存最终实体，还保存每一次合并何时发生、为什么发生。
2. **比较两种信息世界。** 同一批样本分别使用当时可见图和事后完整图，直接测量未来信息带来的差异。
3. **研究节点身份本身的泄漏。** 过去很多工作只删除未来边；本项目检查“节点是如何被定义的”是否已经使用未来信息。
4. **提供可复现的评测协议。** 以后更换GNN也能在同一严格协议下公平比较。
5. **研究结果容易展示。** 时间轴、实体拆分／合并、边变化和模型置信度都能形成清楚的交互演示。

### 选择它的优点

- 与原申报书最接近，仍然研究Bitcoin实体图、GNN、时间信息和识别系统，路线调整容易解释。
- 可以复用现有252M图、已有模型、数据处理经验和BitRiskLens展示系统。
- 创新主要来自数据与评测问题，不依赖某个新GNN一定刷出更高分；即使复杂模型不占优，也可能得到有价值的结论。
- 问题有明确机制、对照和停止条件，答辩时容易说明“为什么旧方法可能不可信、我们怎样验证”。
- 能形成数据构建、评测协议、实验、论文和交互系统多种成果，适合大创完整交付。

### 选择它的缺点

- 需要重新处理原始链数据，不能直接从现有最终图恢复；数据工程量和验证难度最大。
- 公开地址标签缺统一发现时间，第一阶段只能做回顾性实体类型敏感性分析，不能直接声称真实在线识别。
- 地址聚类只是启发式结果，不是真实主体真值；结论措辞必须保守。
- 最终可能得到“影响很小”的负结果。此时应停止主创新，而不是靠增加模型包装。
- as-of分区会让一个最终实体拆成多个历史组件，标签如何投影和比较需要严格协议，否则容易制造新的不公平。

### 最大风险

需要从公开链数据重新构建地址合并过程。现有252M数据库只有最终实体和聚合边，无法倒推出历史分区。若小规模实验发现未来合并几乎不影响图结构或模型结论，这个创新主张应停止。

## 方向二：延迟揭示标签下的找零关联识别

### 通俗理解

一笔Bitcoin交易通常有付款输出和找零输出。交易刚发生时，我们可能不知道哪个是找零；几天或几个月后，找零地址与旧地址共同花费，才提供新的关联证据。

这类似考试后很久才公布部分标准答案：较早公布答案的题可能更简单。如果只拿“已经公布答案的题”训练和测试，成绩会被高估。

### 要做什么

1. 对每笔候选交易记录发生时间`T`。
2. 按区块和区块内顺序重放后续交易，找到关联标签第一次可以被推断的时间`D`。
3. 只使用`T`之前可见的交易特征预测输出关联关系。
4. 对截止日期仍未揭示的样本保留“尚不知道”，不能把它们删除或当作负例。
5. 比较普通静态随机切分、严格时间切分、删失校正和允许拒判的方法。
6. 在不同时期的钱包行为上测试，判断方法能否适应新的交易习惯。

### 解决什么问题

它解决的是**标签来得晚且来得有偏**的问题。传统训练数据更容易收录较快暴露关联的交易，模型可能只学会识别这些容易样本，却在真实未来数据上失效。

### 已有研究做到哪里

[Möser与Narayanan](https://doi.org/10.1007/978-3-031-18283-9_19)已经利用未来交易揭示过去找零，并研究多种找零启发式。他们的公开标签和方法证明这个机制真实存在，但没有记录每条样本的揭示延迟，没有把未揭示样本作为右删失数据处理，也没有执行严格的未来时期评价。

我们已经重放公开数据前8条记录：首次花费延迟从0到6070个区块不等，其中一半还需要追踪中间地址合并，不能把“第一次被花费”简单当成“标签揭示时间”。

### 创新点在哪里

1. 将“标签什么时候才可知”正式纳入数据集，而不是只保存最终答案。
2. 把未揭示样本当作右删失数据，避免只研究容易得到标签的样本。
3. 严格禁止使用交易之后的特征，再测试静态评测高估了多少。
4. 允许模型拒判，并同时报告准确性和覆盖率，避免强迫系统对证据不足的交易下结论。

### 选择它的优点

- 科学问题集中，标签延迟和右删失可以清楚形式化，容易形成一条完整研究主线。
- Bitcoin链数据公开，不需要依赖商业数据库；已有小样本重放已经证明揭示时间原则上可以恢复。
- 低成本阶段只需处理有限交易及其后续关系，比重建完整实体图更容易快速判断方向是否成立。
- 可以自然产生时间切分、删失分析、拒判和跨时期稳健性等严谨实验。

### 选择它的缺点

- 标签来自未来启发式关联，不是真实钱包权限或实体身份，研究结论上限受到限制。
- 与原申报书的实体级GNN分类距离较远，单独作为主方向需要更多行政解释。
- 公开标签没有直接提供揭示交易和揭示高度，仍需逐条重放与动态连通分析。
- 容易被评委理解成“找零识别的小改进”，需要讲清标签选择偏差和时间评测价值。
- 如果简单时间切分已经解决大部分问题，删失方法可能只剩较小增量。

### 最大风险

未来共同花费只是链上启发式关联，不是真实钱包所有权证明。因此本方向只能称为“找零／地址关联证据预测”，不能称为识别真实主体或非法交易。它也比方向一更偏离原申报书中的实体级GNN任务，所以排在第二。

## 方向三：多观察点内存池分歧与结果校准

### 通俗理解

Bitcoin交易在确认进区块前，会先在节点之间传播。不同地区、不同网络和不同策略的节点，同一时刻看到的交易并不完全相同。

这像几台服务器同时监听新闻：一台没收到消息，不代表消息不存在，也不代表它主动拒绝了消息。只看单个节点，可能误判交易是否会确认、是否被替换，或者网络是否出现异常。

### 要做什么

1. 在多个地理位置和网络环境部署相互独立的Bitcoin节点。
2. 同步记录原始交易、首次看到时间、手续费、祖先交易包、冲突／替换、节点接纳与移除结果、最后是否确认。
3. 区分“没有看到、策略拒绝、后来驱逐、被替换、缺少父交易”等不同原因。
4. 研究增加观察点后，交易结果预测的准确性和置信度如何变化。
5. 给定有限节点预算，选择最有信息增量的观察点，并为不确定结果提供拒判或置信区间。
6. 做一个传播地图和交易生命周期面板，展示不同观察点为何得出不同判断。

### 解决什么问题

它解决的是**单个观察点不能代表整个Bitcoin网络**的问题。区块浏览器、交易监控和确认预测若只依赖一个节点，容易把局部现象误认为全网事实。

### 已有研究做到哪里

[Albrecht与Karame 2026](https://doi.org/10.1145/3774904.3792404)已经使用16个地理观察点开展约196小时的Bitcoin内存池审计，证明多观察点研究有现实价值。但公开数据主要包含交易哈希和各观察点首次时间戳，没有原始交易、手续费、交易包、冲突和本地接纳状态，无法公平比较强基线，也无法解释“为什么没有看到”。

已有工作也研究过交易传播、手续费与确认时间，Bitcoin Core本身已有大量内存池策略测试。因此，单纯部署更多节点或画传播图不构成创新。

### 创新点在哪里

1. 构建包含完整预测时状态的多观察点数据，而不是只有到达时间。
2. 首次把“未看到”和“明确拒绝”等状态分开，减少错误解释。
3. 研究观察点数量、位置和网络差异对预测置信度的影响。
4. 在固定观察预算下选择节点，并输出可校准的不确定性，而不是只给一个确认／不确认答案。

### 选择它的优点

- 场景直观，直接服务交易监控、确认预测和网络测量，现实意义容易理解。
- 数据由自己的节点日志产生，若采集协议正确，接纳、移除和确认等结果比启发式实体标签更客观。
- 多地区传播地图和交易生命周期非常适合现场演示，系统成果感强。
- 可同时研究网络测量、系统、数据分析和机器学习，不必完全依赖GNN。

### 选择它的缺点

- 现有公开数据字段不足，必须重新部署和长期运行多个独立节点，数据获取失败会直接卡住方向。
- 不同节点的网络连接、时钟、策略和版本会同时变化，若控制不好，很难判断差异原因。
- 与原申报书的实体识别主线联系最弱，可能被认为换了研究对象。
- 已有交易传播和内存池审计研究较多，只有“多部署几个节点”或“做一个预测模型”不够创新。
- 采集窗口内可能缺少足够的冲突、替换或异常案例，导致无法支持强结论。

### 最大风险

必须长期稳定运行多个真正独立的节点，并保证时钟、日志和软件版本可比。若只有同一台机器上的多个连接，就不能冒充多观察点。它与原申报书的实体GNN分类联系较弱，因此排在第三。

## 为什么Payjoin没有进入前三

Payjoin仍适合作为工程保底：可以做协议一致性检查、固定测试向量和隐私风险演示。但输入所有权分区、多属性钱包指纹、协作交易仿真以及跨实现一致性问题已经有较直接的论文、项目代码和公开讨论。剩余研究空间较窄，更适合保证项目能够交付，不适合作为当前最强创新主线。

## 当前建议

若只选一个主方向，选择方向一。它与原申报书距离最近，能复用现有252M实体图、GNN基线和展示系统，又把核心贡献从“更换模型结构”提升为“修复数据与评测是否可信”的问题。

方向二可以并入方向一，负责解释未来关系如何产生；方向三保持独立替代。主方向确认后，应先冻结信息截止、地址单位、聚类规则、标签投影、切分和No-Go条件，再做小窗口无模型审计。只有核心影响真实存在，才投入完整构图和GNN实验。
