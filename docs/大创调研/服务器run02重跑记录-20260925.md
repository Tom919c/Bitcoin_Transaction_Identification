## 5. 一个操作事故与教训

用 ssh 前台启动后台任务时，命令里含 `setsid nohup … & sleep N` 这类组合会被沙箱 **SIGTERM**（表现为
exit 1、无输出）。但此时**服务器侧进程其实已经起来了**。连续四次"失败"的启动累积出**四个并行实例**
（PID 185134/185137、185173/185176、185195/185198、185219/185222 各自成对），它们争抢同一个状态库的
I/O 并写同一个 `evaluation.json`。

处置：先杀父脚本（`run_s0_run02_retry`），再杀 `setsid` 脱离会话的 python 子进程；清空被污染的
`s0_run02_retry.log` / `.out` 与输出目录；重新启动一次并**不等待**，之后单独核查实例数确认为 1。

**教训**：ssh 前台命令里带 `&` + 长时间 `sleep` 不可靠。正确做法是发起后立即返回，隔一段时间用独立
命令核对进程。核对时必须 `grep -c` 计数，不能只看 `head -3`（四个实例时只显示前三个会漏判）。
