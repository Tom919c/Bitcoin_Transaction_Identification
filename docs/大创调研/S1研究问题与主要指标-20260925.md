# S1 候选方案：目标、评测单位、主要指标与停止条件（一页）

日期：2026-09-25（同日修订）。性质：**S1 协议草案的输入，不是 S1 协议本身。**

> **2026-09-25 修订说明**：导师裁定——**暂不认可把 `overlap(K)` 定为 S1 唯一主指标，也不批准启动"无标签 S1"**；`overlap(K)` 可衡量稳定性，但在评测单位、候选打分方式与 `K` 未定义时**不能证明复核质量或使用者收益**；VASP 合规调查员只是**拟议使用者**，不能据此声称合规效用。
>
> 据此本文件从"单一主指标提案"改为**并列两条候选路线**，由导师据证据选择。**S1 协议草案现在就应起草；执行必须等草案审核。**

## 0. 写作纪律（不得违反）

- 使用者一律称**拟议使用者**，不得据其声称合规效用、也不得用"当时可识别""历史部署性能"措辞；
- 不做"唯一主指标"预设；两条路线的指标各自定义；
- 无标签结构分析须**先说明它比已完成的 S0 多回答什么问题**，否则不值得做。

## 1. 拟议使用者

**某 VASP（虚拟资产服务商）合规调查组的一名调查员。**

- 历史时点：协议中的一个 cutoff `t_j ∈ {181440, 199584, 215712, 225792}`。
- 他在 `t_j` 时可能面临的决定：在人工复核预算有限时，决定把哪些实体放进复核队列；可用信息**只有** `t_j` 之前可见的链上与派生信息。

**边界（导师裁定）：** 这是**拟议**使用者，不是已确立的部署场景。本阶段**不声称**任何合规效用、复核质量提升或使用者收益。

## 2. 两条候选路线

### 路线甲：回顾性实体类型分析

| 项 | 内容 |
| --- | --- |
| **目标** | 检验分区版本（`C_{t_j}` vs `C_{T_j}|V_j`）是否改变实体类型标签的投影与冲突结构 |
| **需要标签** | 是。11 类实体类型标签（来源见 `S1标签一手来源追查表-20260925.md`） |
| **标签时间要求** | **不要求**逐记录可得时间（故称"回顾性"），但**必须标注为回顾性敏感性分析** |
| **评测单位** | 待定义：`(window_id, filter_profile)` 下的 script-level label anchor 配对集；须定 B/C 实体匹配与去重规则 |
| **候选主要指标** | 标签投影冲突率 / 未投影比例 / 配对标签一致率 / （标签可用时）Macro-F1 等的 B/C 配对差 |
| **停止条件** | 待与导师确认判据后写定；若标签不可构造则本路线不成立 |
| **与 S0 的关系** | S0 已回答"结构差异存在"；本路线回答"结构差异是否传导到**标签层**" |

### 路线乙：无标签结构分析

| 项 | 内容 |
| --- | --- |
| **目标** | 在无标签条件下，检验分区版本对**实体名单稳定性**的影响 |
| **需要标签** | 否 |
| **必须先回答的问题（导师要求）** | **它比已完成的 S0 多回答什么问题？** 见下 §3 |
| **评测单位** | 待定义：`(window_id, filter_profile, K)` 下的实体队列 |
| **候选主要指标** | 名单重叠率 `overlap(K) = |Q_B(K) ∩ Q_C(K)| / K`，`K ∈ {1%, 5%}` |
| **停止条件** | 待定 |

## 3. 路线乙必须先回答的问题（导师指定）

导师原话要点：**无标签名单稳定性可列为另行定义的结构探索问题；是否值得做，先由协议草案说明它比已完成的 S0 多回答什么问题。**

我的初步回答（**待导师判定，不是结论**）：

| S0 已回答 | 路线乙可能多回答 |
| --- | --- |
| 结构差异**存在**且量大（`p_merge`/`p_rewrite` 的 4/4 窗口均过 1% 门槛） | 这些差异**是否改变按某个冻结评分函数排出的实体名单** |
| 差异以 `p_merge`/`p_rewrite` 等**比率**表述，作用于脚本级支持与交易 | 差异是否**改变候选集合**（选定 `K` 下的交集），即从"比率"到"名单" |
| 未涉及任何优先级排序 | 涉及一个**明确的排序与截断规则** |

**但这里有一个必须自己指出的弱点**（否则等于回避导师的批评）：路线乙的结论**完全取决于评分函数与 `K` 的选择**。若评分函数不被认可为"调查员会用的规则"，则 `overlap(K)` 只说明"某个任意规则下名单不稳定"，**推不出复核质量或使用者收益**。因此路线乙若要成立，**必须先冻结一个可辩护的评分函数**，且该函数不得依据结果调整。

**由此的直接含义：`overlap(K)` 在评分函数未冻结前不应被写为"主要指标"。** 本文件据此不把它列为唯一主指标。

## 4. 标签冲突与缺失处理

依据 S0 协议 §9 与来源侧实际做法：

| 情形 | 处理 | 依据 |
| --- | --- | --- |
| 同一 cluster 内多个不同实体类型 | 记为**冲突**，不按多数票覆盖 | 协议 §9 明文 |
| 冲突的最终处理（移除／拒判／仅描述） | **S1 协议须明确定一种，并固定分母** | 协议 §9 要求 |
| `-1` | 保持**未标注**，不作负类 | 协议 §9 明文 |
| 无法投影的标签 | 记录未投影比例，**不静默丢弃** | 协议 §9 要求 |
| 来源侧既有做法 | 原论文对冲突 cluster **直接不标注** | arXiv 2411.10325 |

**待决（拟作决定，须导师审核）：** 原论文"冲突即不标注"会丢失信息且不可追溯；建议改为**标记冲突 + 明确移除规则 + 报告分母**。此为方法论变更，**不在草案中单方生效**。

## 5. 基线（两条路线共用，或按路线裁剪）

按协议 §9 首轮清单，**先跑最简基线，不预设 GNN 领先**：多数类、逻辑回归、一个树模型、MLP、现有 GraphSAGE 与 EGS（历史资产复用）。

**一个前置判断：** 若简单非图模型已能充分解释 B/C 差异，**不新增 GNN 架构**（章程 §6 明文）。

**纪律：** 测试集只在配置、manifest 与 decision log 锁定后**打开一次**；每个学习模型用同一组五个种子；最多 20 个验证集超参配置；**不新增 GNN 架构或预训练任务**。
