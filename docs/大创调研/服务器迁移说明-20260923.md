### 3.1 存储拓扑与读写性能（2026-09-23 实测）

块设备只有两块：`/dev/sdb` 116.4 TB、`ROTA=1`（**机械盘**）、型号显示为 `LOGICAL VOLUME`（硬件 RAID），挂载于 `/workspace`，ext4、`stripe=512`；`/dev/sda` 447 GB、`ROTA=0`（SSD），承载系统。

`/` 是 overlayfs，其 `upperdir` 位于 `/home/docker_data_root/overlay2/...`，与 `/workspace` 同在 `/dev/sdb` 上（`df` 对 `/` 与 `/workspace` 都报 116 TB / 已用 19 TB）。因此 **`/home/chenquan` 与 `/workspace/chenquan` 落在同一块阵列上，没有设备级差异**，差别仅在于 overlay 多一层元数据间接。

实测（512 MiB，测试期间两条网络传输仍在运行，存在噪声）：

| 测试              | `/workspace/chenquan` | `/home/chenquan` |
| --------------- | --------------------- | ---------------- |
| 写（`O_DIRECT`）   | 87.3 MB/s             | 91.9 MB/s        |
| 写（缓冲 + `fsync`） | 未测                    | 251 MB/s         |
| 读（`O_DIRECT`）   | 770 MB/s              | 902 MB/s         |

读数字偏乐观：测试文件刚写完，RAID 控制器缓存仍在服务它。直写只有约 90 MB/s，说明 `O_DIRECT` 路径绕过了控制器写缓存。

结论：两处路径吞吐相当，选 `/workspace/chenquan` 的理由是归属清晰、权限 700、且少一层 overlay 间接，**不是速度**。真正需要留意的是 `/dev/sdb` 为机械阵列：顺序读可达数百 MB/s，随机写与直写较弱。这对 S0 评估的 SQLite 临时排序、以及 S1 的随机小文件读取都可能不利；`/dev/sda` 尚有约 382 GB SSD 空间，可考虑作热点数据暂存。这也意味着先前"服务器单次约 7 小时"的估计所依据的"服务器存储更快"这一前提并不成立，该估计的区间应视为偏乐观。

## 6. 校验设计

校验不依赖"文件数对了就算完"，而是逐对象比对哈希：

1. **transactions** 用 manifest 绑定的 `aws_btc_transaction_byte_freeze_v0_1_20260910.json` 中逐对象的 `local_sha256` 与 `size`，对 1890 个对象全覆盖比对。这是最权威的一路，因为该冻结文件的哈希由 `configs/data/aws_btc_s0_source_manifest_v1_1.json` 绑定。
2. **blocks 与 transaction 边车** 比对本机生成的 SHA-256 清单（`blocks_local_sha256.txt` 3794 条、`tx_sidecar_local_sha256.txt` 1892 条）。
3. **`utxo_v0_2.sqlite`** 比对 `6cafc290b8e3b951417c85c5b6dd431e71c3d0c548ac45bdc6a7bdee4a34d924`，该值正是 Research Passport 记录的交易语义状态哈希，属权威参照。
4. **`s0_union_v1_1.sqlite`** 比对 `1f1bf354519af4dcc1e0cc3ae3da0c670d057bd5897db6bf806e3442bc078205`，即 provenance 运行绑定的状态库哈希。

校验器为服务器侧 `verify_dataset_transfer.py`，输出逐项计数与 `PASS/FAIL`，对缺失、哈希不符、大小不符分别计数并给出样本。

## 10. 风险与未决事项

1. **上行链路是唯一瓶颈**，约 19 Mbit/s。曾评估让服务器直接从 `s3://aws-public-blockchain/v1.0/btc/` 匿名重取 transactions 与 blocks 以绕开本机上行，**已实测否决**：服务器下载最大对象（175.5 MB）时约 0.74 MB/s，五个抽样对象聚合 0.41 MB/s，均低于本机上行，原因是服务器位于国内高校出口、访问 S3 的国际带宽受限。因此 73 GB 约 8 小时的传输时间是链路下限。
   该探测同时得到一个有正面价值的旁证：**抽样的 5 个对象（175.5 MB、163.5 MB、161.5 MB、8.1 MB、0.01 MB）哈希全部等于 byte freeze 记录的 `local_sha256`**，即公开桶当前仍提供与 2026-09-10 冻结字节一致的内容，冻结可被公开源独立复现。注意这只是 5/1890 的抽样，且公开桶未启用版本控制（原始对象 `VersionId=null`）；权威校验仍是本地传输后对全部 1890 个对象逐一比对，S3 抽样不能替代它。
2. **服务器仓库没有 remote**，本地与服务器之间靠 `git bundle` 同步。远端 `origin` 为 `https://github.com/Tom919c/Bitcoin_Transaction_Identification.git`，其可见性未核验；推送前必须先确认是否公开并取得授权。
3. **本机长跑作业仍无法脱离宿主进程树**：WorkBuddy 桌面版约每天重启一次并连带杀掉后台子进程，`schtasks` 在安全策略黑名单内。S0 评估对是当前唯一必须在本机完成的长跑作业，仍有被中断风险。
4. `/workspace` 根目录属 `root`，本机用户只在 `/workspace/chenquan` 下有写权限；不要把产物写到 `/workspace` 其他位置。
