## 3. 与本项目的最近邻关系

### 3.1 实质重叠

BitLINK 已经明确提出并实现“跨时间把分离地址簇链接起来”的任务，也使用共同输入簇、时间活动序列、自监督伪标签和人工审查。因此，以下方向不再具有可信的新颖性主张：

1. 仅提出一种新的时间序列或自监督模型来寻找 flush 后继簇；
2. 仅声称首次研究 Bitcoin 地址簇的跨时期链接；
3. 仅以更高 top-k、G-mean 或新的编码器替换 BitLINK 模型；
4. 把 carry-on cluster 发现直接改写成“未来聚类”而不改变研究对象和评测问题。

### 3.2 明确差异

当前候选主线的研究对象应固定为**历史时点可见的聚类状态与其后续重写**：在每个截止高度 `t` 仅用当时可见交易构造 `C_t`，再与较晚时点 `T` 的 `C_T` 对比，测量未来共同花费导致的合并、实体单位变化、标签映射变化和历史评测偏差。它不是预测某个 flushed cluster 的后继簇，也不以服务归属发现或链式扩展为主要任务。

可检验的边界是：

| 维度 | BitLINK | 本项目候选主线 |
|---|---|---|
| 主要问题 | 哪个簇与已知 flushed cluster 在时间模式上链接 | 使用最终聚类或未来共同花费会在多大程度上改写历史实体图与评测 |
| 基本对象 | 全链共同输入簇对与其时间序列 | 版本化聚类状态 `C_t`、重写映射 `C_t -> C_T` 和由此变化的图/标签/指标 |
| 主要贡献形态 | 候选检索模型与人工链式分析 | as-of 数据协议、泄漏审计、重写量化、失真边界和可信评测 |
| 部署语义 | 离线寻找 carry-on clusters | 在信息截止时间约束下重现历史可知状态，防止未来信息进入训练或测试单位 |
| 真值角色 | WalletExplorer、人工筛选和链下确认 | 聚类变化本身来自确定性链上重放；实体类型或风险标签仍须单独记录来源与可得时间 |

BitLINK 因而是必须正面讨论的最近邻与反例来源，但现有全文证据不等价于它已经研究或解决了 `C_t -> C_T` 引起的历史图评测失真。

## 4. 对 BitLINK 评测的风险审计

以下内容区分“原文明示”和“本项目推断”。推断不能写成对 BitLINK 实现的既定事实，需在取得并运行其代码后再升级核验状态。

1. **潜在 as-of 聚类泄漏（推断，待代码核验）**：Step 1 描述先在截至 2022-10-16 的全链上完成共同输入聚类，随后为簇生成时间序列。若早期样本的簇成员包含其后才通过共同花费并入的地址，则早期时间序列和候选单位使用了未来可见的 `C_T`，不是当时可构造的 `C_t`。原文没有在已核验章节中说明按每个样本截止点重放聚类。
2. **潜在时间窗口未来信息（推断，任务语义相关）**：输入以 flushing point 为中心截取 32 天，且伪负例可使用其他簇的完整时间序列。这适用于离线回溯任务，但若主张在线或当时可部署识别，则必须另行规定决策时刻和窗口右端的信息可得性。
3. **拆分充分性未证实**：正文只明确说明训练与验证的 prefix clusters 互斥；没有在已核验章节中证明 suffix cluster、服务实体、时间段或共同交易邻域也隔离。因此不能仅凭该声明排除实体级或关系级重叠。
4. **测试窥视风险**：将 W.E. 与 M.L. 的逐 epoch 曲线用于观察泛化，并进一步让其中一个承担早停验证、另一个承担测试，会使两者的角色依实验阶段变化。若双向结果被共同用于方法选择或叙事，就不是一次性封存测试集；具体运行次数和选择过程仍待代码/日志核验。
5. **选择偏差与真值边界**：W.E. 正对由人工筛选，M.L. 来自两个服务并使用链下泄露信息确认；负候选还有规模与共享对手方过滤。这些集合适合验证特定候选检索场景，但不能自动代表全链地址簇、所有服务或严格未来部署分布。
6. **统计证据不足**：五轮均值不等于数据采样不确定性。正文声称“无统计显著差异”但相邻位置未给检验、置信区间、效应量或独立重采样单位，不能据此复用显著性结论。
7. **人工决策不可与模型指标混同**：最终链路包含主观检查、先验和 CoinJoin 排除，属于人机流程。top-k 分类指标不能单独证明链式归属的端到端准确率，更不能证明真实实体所有权。

## 5. 对 Gate 3A v1.0 的强制影响

在进入 S0 前，正式协议必须新增或明确以下约束：

1. 每个 cutoff 独立重放共同输入聚类，只允许高度不超过 cutoff 的输入；最终聚类只作为事后比较对象。
2. 特征、候选集、标签和聚类单位分别记录 `event time`、`available time` 与生成版本；不能以最终簇成员回填历史特征。
3. 训练、验证和测试至少审计地址、`C_t` 实体、`C_T` 最终实体、服务标签和交易邻域五种重叠；任何允许的重叠必须预注册。
4. 测试时段与测试实体一次性封存，不逐 epoch 观察测试曲线，不互换验证/测试角色后共同选择方法。
5. 以地址或最终实体标签映射到 `C_t` 时，显式报告一对多、多对一、未标注和标签公开时间；实体类型不能转写为 illicit、fraud 或 AML risk。
6. BitLINK 作为最近邻方法进入任务定义矩阵和相关工作；仅当本项目新增 carry-on cluster 检索任务时，才需要将其作为直接模型基线。对当前重写审计问题，它主要是协议对照和泄漏反例来源。
