# 正式申报书与候选方向适配审计

日期：2026-09-01；2026-09-04补充数据门、源码与最近邻核验

状态：Gate 2方向重审；不等于学院批准变更题目或技术路线。

## 1. 证据来源

用户于2026年9月1日提供《电子科技大学大学生创新训练项目计划申请书》的文字转录，并明确说明这是项目申报书。当前读取的是PDF内容转录文本，未直接检查签字盖章页的原始扫描件；研究方向判断按用户提供内容执行，不保存联系电话、邮箱等个人信息。

申请书的核心约束是：

- 项目名称：“基于图神经网的非法比特币交易识别”；
- 研究对象：Bitcoin交易网络，节点为地址／钱包，边为资金流；
- 主要任务：实体多分类、违规／风险模式识别；
- 明确方法：MLP等非图基线，GCN、GAT、GraphSAGE、APPNP，残差GraphSAGE和半监督学习；
- 申报创新：残差GraphSAGE、子图分类、异构图；
- 交付：标准化图数据、预处理代码、模型与对比报告、论文初稿、PPT和GUI演示系统；
- 项目期限：一年。

申请书允许在Bitcoin交易图、时间属性、子图／异构图和系统实现范围内调整方法，但把GNN实体／风险识别写成了主任务。因此，完全改成独立的地址关联标签预测会构成实质路线变化。

## 2. 必须纠正的历史表述

现有数据的监督标签`0–10`是实体类型，`-1`是未标注背景。INDIVIDUAL、EXCHANGE、MINING、FAUCET等不表示非法；BET、GAMBLING、MIXER等类别也不能仅凭类别名称自动等同违法或AML风险。

后续结题材料应把任务表述为“实体类型识别、链上关联证据与审查辅助”，并对有独立证据支持的风险场景另行说明。不能继续把11类分类成绩直接写成“非法交易识别准确率”。

## 3. 两种C1路线

| 路线 | 科学问题 | 申报书适配 | 当前状态 |
|---|---|---|---|
| A：独立延迟关联标签 | 静态完整快照高估多少对未来启发式关联标签的预测；如何处理揭示延迟、删失和拒判 | 同属Bitcoin图可靠性，但预测单位、标签和主方法都偏离原GNN实体分类 | 已有最小重放和协议草案，仍受代理标签与删失假设限制 |
| B：严格as-of实体图 | 最终地址聚类是否把未来才出现的关联回填到历史实体图，从而改变时间外GNN实体分类、校准和有限预算结论 | 直接连接原申报的数据构图、GNN分类、时间属性和系统交付 | 申报适配更强，但预测单位与标签时点尚未通过数据门 |

当前不把A和B混成一个任务。B只有通过第6节数据门，才可替代A成为主方向。

## 4. B路线的直接数据依据

[Schnoering与Vazirgiannis 2025数据论文](https://www.nature.com/articles/s41597-025-04684-8)明确记录：

1. 地址按区块顺序应用启发式并不断合并，最终cluster成为图节点；
2. 得到最终地址到cluster映射后，再构造cluster间交易边和节点属性；
3. CoinJoin依靠规则检测并从聚类与构图中排除；
4. 技术验证任务是对最终cluster节点做实体类型GNN分类。

因此，原项目不是与C1无关：其节点身份、边和`cluster_size`等属性确实建立在启发式地址聚类上。若研究声称在历史时点或未来时期部署，最终cluster可能包含当时尚未出现的合并关系。这是需要验证的泄漏机制，不是已经证明的错误。

若任务仅是对完整历史结束后的最终cluster做回顾性分类，使用最终聚类并不自动构成泄漏。B必须比较明确部署时点下的as-of图，不能仅因“用了全链”就宣布原论文无效。

2026-09-04进一步核对官方构图仓库固定revision `3becbc44a951abbe1e85d374a66340a639059d1c`：

- `steps/populate_alias.py`按区块读取输入／输出，使用Union-Find累计合并，结束后才写入唯一的`node_id -> alias`表；代码没有保存每次union的区块高度、规则来源或历史版本；
- `features/cluster_transaction_edges.py`随后查询这张alias表构造cluster级关系；
- 因而未来区块触发的union会进入最终alias。若把该alias用于早期时点任务，节点身份本身已含截止时点之后的信息；仅删除未来边或重算特征不能恢复早期分区。

这证明机制存在于官方流水线，但尚未证明它对分类结果有实质影响。

## 5. B路线的候选任务定义

在固定截止时点`t`：

- 仅用`t`及以前交易重建地址分量和实体图`G_t`；
- 用完整快照最终分量构造诊断oracle `G_T`；
- 在同一地址样本宇宙上记录最终cluster相对`G_t`发生的跨时合并、节点／边变化和标签聚合；
- 先比较规则与tabular强基线，再比较原申报中的GraphSAGE／GAT等GNN；
- 评价实体类型分类、校准、错误—覆盖和有限审查预算，不评价“是否违法”。

若实体标签只能由最终cluster回填给历史子分量，结果只能称为“固定最终标签在不同构图投影下的敏感性”，不能称为真实的历史在线实体识别。

## 6. B路线最小数据门

训练GNN前先做不含学习模型的致命审计：

1. 取得同一批地址在截止时点的as-of分量、最终cluster归属和地址级外部标签；
2. 明确标签来源、采集／公开时间；缺时间时冻结为回顾性标签，不冒充当时可用监督；
3. 量化最终cluster造成的跨时合并比例、训练测试分量交叉、边重写和标签冲突；
4. 使用保守与宽松CoinJoin／协作交易过滤重复审计；
5. 排除差异仅由节点数量或特征尺度改变造成；
6. 补查是否已有等价的“最终聚类对时间外GNN实体分类影响”工作。

No-Go条件：

- 无法得到地址到as-of／最终cluster的可审计映射；
- 标签只能依赖未来cluster定义，且无法形成诚实的固定目标；
- 过滤规则一变，核心差异方向翻转；
- 差异只表现为普通特征重算或模型分数下降，没有独立单位上的稳定机制；
- 最近邻已给出等价问题和评测。

### 2026-09-04本地资产审计

通过只读事务检查当前PostgreSQL实例：

- `node_features`约252,148,848行，只含最终`alias`、聚合统计、首末交易高度、cluster统计和实体类型标签；
- `transaction_edges`约785,954,752行，只含最终alias之间的端点、`reveal`、`last_seen`及聚合金额／次数；
- 数据库没有地址表、地址到alias映射、原始交易输入输出、聚类证据边或union历史。

因此现有252M图无法逆推出as-of分区。该结果关闭“直接在现有库上重算即可”的路线，但未关闭B：Bitcoin链数据公开，官方流水线已给出原始交易到alias的构建入口；复现时应把union事件追加记录为`(address_a, address_b, block_height, intra_block_order, heuristic, filter_version)`，再生成as-of与最终两种图。

地址标签文件只提供地址、实体／类别和来源，未提供统一的发现时间。第一阶段因此采用固定回顾性实体类型目标，只研究构图投影与评测敏感性；不得宣称真实在线监督或非法活动识别。若后续能为一部分标签核验公开时间，再单列前瞻实验。

### 最近邻边界

双链检索与全文核验得到：

- Schnoering–Vazirgiannis数据论文给出最终实体图和随机节点切分，没有历史分区或严格时间外评价；
- Müller等2026用七家欧洲CASP报告数据评估多输入启发式，全文明确是静态快照，没有下游GNN或纵向as-of分区；
- Möser–Narayanan研究未来交易揭示过去找零及聚类增强，但没有比较as-of／最终分区对实体类型GNN评测的影响；
- Maganti 2026研究Elliptic交易节点图的严格时间协议，没有地址到实体聚类或未来合并。

截至本次检索，尚未发现与B完整等价的工作。该表述只是当前证据范围内的创新性判断，不是全球首次证明。

## 7. 交付叙事

若B通过，推荐把项目组织为：

1. 旧实体类型GNN和BitRiskLens作为复现基础；
2. 严格as-of实体图构建与泄漏诊断作为核心创新；
3. 强非图基线与GNN在严格协议下的公平比较；
4. 在系统中展示cluster合并证据、信息截止、标签冲突、模型校准和拒判。

建议内部副标题：

> 面向比特币实体识别的严格按时可见构图与可信GNN评测

这条路线保留原申报的GNN、实体分类、时间图和GUI交付，同时把创新从“换残差模块”提升为新的可证伪评测问题。

## 8. 当前裁决

正式申报书关闭了“原项目口径未知”问题。源码、数据库和最近邻审计后，当前Gate 2建议调整为：

1. 建议主方向B：**面向比特币实体识别的严格按时可见构图与可信GNN评测**；
2. A不再作为平行主线，改为B中的一种“未来关系揭示”机制和标签时点辅助实验；
3. Payjoin保留为协议一致性检查器和固定测试向量的工程保底，不承担核心创新；
4. B先在小区块窗口和地址标签交集上执行不训练审计；若跨时合并、节点重写、标签冲突和评测差异均不具实质性，则按No-Go退回候选比较；
5. 用户确认B后才冻结Gate 3A并编写重建代码，确认前不训练新模型。

B优于A的主要原因不是工作量，而是它直接修正原项目“最终聚类＋全期聚合＋随机切分”的可信性问题，能同时支撑数据、评测、GNN对照和可解释演示；A的标签是未来启发式关联，真值上限更弱且偏离原申报。B优于Payjoin，是因为Payjoin的多属性指纹、输入所有权分区、仿真与一致性策略已有直接实现，剩余空间更像窄增量。

指导教师是否同意技术路线调整仍需人类确认；该事项不阻止当前只读数据审计。
