# S1 标签可得时间准备度审计

日期：2026-09-13

状态：证据盘点完成；严格历史部署语义下的 S1/S2 当前不具备标签准入条件。本结论不影响无标签 S0，也不授权读取、投影或训练任何标签。

## 1. 范围与边界

本轮只检查已提交的文档、配置、代码和实验登记，没有打开 `data/`、数据库、环境变量或实际标签行。目标是判断仓库现有元数据能否形成截止时间为 `t` 时实际可得的标签集合 `L_{<=t}`，而不是评估标签分布或模型效果。

这里严格区分：

- `entity type`：仓库中的 11 类实体类型枚举；
- `illicit activity` 与 `fraud`：当前没有独立、可核验的任务定义或真值；
- `AML risk`：当前没有独立风险标签。代码中的二元分组只是项目内代理映射，不是外部风险真值；
- `-1`：未标注图上下文，不能当作正常类、负类或未知非法类。

### 2.1 公开一手来源增量核验

2026-09-13 使用独立公开检索链核验了以下一手来源：

- Scientific Data 数据论文 [*Bitcoin research with a transaction graph dataset*](https://doi.org/10.1038/s41597-025-04684-8) 的 “Node labels” 与 “BitcoinTalk” 小节说明：论坛抓取记录包含帖子发布日期，抓取在 2023 年末进行；最终标签还混合交易所官网、DefiLlama、既有勒索软件数据集等来源。正文同时明确记录论坛错误信息、英语社区选择偏差和模型抽取误差等限制。
- 官方 [`BTCGraphLabeling`](https://github.com/hugoschnoering2/BTCGraphLabeling) 的 `gather_all_sources.py` 将最终表固定为 `address, entity, category, source`；汇总 BitcoinTalk 处理结果时累计实体名称、类别与出现次数，但写出的 `addresses.csv` 不含帖子发布日期、抓取时间、来源 URL、置信度或更正时间。因此，论文所述上游帖子时间没有随最终公开标签表保留。
- arXiv v1 [`2609.01942`](https://arxiv.org/abs/2609.01942v1) §6.3.1 在区块 550,000--700,000 中使用约 100,000 个地址的实体名称标签，排除 individual，并把同名／异名地址对作为聚类评测真值；它没有把标签首次可得时间作为实验 cutoff，也没有补回最终表缺失的时间字段。

本轮查询围绕 Zenodo `22239038`、上述论文精确标题、`BTCGraphLabeling`、`BitcoinTalkScrapper` 和 `addresses.csv` 的标签来源／时间字段展开。检索结果只用于定位；以上结论均回到论文正文或作者官方仓库核验。新增证据把“所有上游时间均未知”收紧为：**BitcoinTalk 原始流水线存在帖子发布日期与批次采集时间，但当前已核验的最终标签表未保留它们；若能取得并版本化原始帖子到标签的逐记录映射，BitcoinTalk 子集可能重建 `L_{<=t}`，其他来源仍需分别审计。**

## 3. `L_{<=t}` 准备度

| 必需维度 | 当前状态 | 原因 |
|---|---|---|
| 标签所指事件或实体状态的发生时间 | 部分 | 有链上交易活动时间，但它不是标签事实的发生时间 |
| 首次发现时间 | 未定位 | BitcoinTalk 帖子发布日期只是候选证据公开时间，不等于标签流水线首次发现时间 |
| 首次公开时间 | 部分 | 论坛帖子发布日期可作为候选公开时间；其他来源和最终标签记录仍未对齐 |
| 本项目采集时间 | 部分 | 论文只给出 2023 年末的批次采集时间，最终表没有逐记录采集时间 |
| 来源、版本与许可 | 部分 | 历史地址表有粗粒度 `source`；逐记录版本和许可覆盖未关闭 |
| 置信度与证据等级 | 未定位 | 没有逐标签置信度或核验等级 |
| 更正、撤销与冲突时间 | 未定位 | 没有版本化状态变化记录 |
| 正类、负类与未标注语义 | 部分 | `-1` 已确定为未标注；11 类不是统一的正负标签 |
| 地址到脚本、历史实体与最终实体的投影 lineage | 未定位 | 现有文档明确记录映射和 union 高度缺失 |
| 删失与冲突处理规则 | 未定位 | 尚无可对真实来源执行的逐标签规则 |

因此，当前不能构造可审计的 `L_{<=t}`。把最终标签回写到历史 `C_t` 会引入与本项目核心问题相同的未来信息风险。

## 4. 当前 Gate 裁决

1. **S0 不受影响。** S0 只测量 `C_t/C_T` 引起的分区与实体图重写，不读取标签。
2. **严格历史部署 S1/S2 暂不准入。** 在逐标签来源、首次可得时间和投影 lineage 关闭前，不得声称历史时点实体类型识别、非法活动识别、欺诈识别或 AML 风险识别。
3. **回顾性敏感性分析仍是条件候选。** 仅当 S0 Go 且后续 S1 协议单独冻结时，才可使用最终可得实体类型标签比较 `C_t/C_T` 对离线模型的影响；结果必须明确降级为 retrospective sensitivity，不能外推为历史部署。
4. **代码中的二元敏感组不是真值。** `risk_binary_label` 不得直接成为 S1 的主标签或论文中的 AML ground truth；如未来保留，只能作为经单独论证的派生分组，并报告每类结果与映射敏感性。
5. **Kaggle 暂不接收标签资产。** 在许可和字段级清单关闭前，Kaggle 双 T4 只作为后续计算路线，不上传本地数据库、地址标签表或未审计标签派生物。

## 5. 解除阻断所需的最小证据包

后续若要冻结严格历史 S1，至少需要：

1. 每条标签的稳定记录 ID、原始实体／地址标识、类别原文、来源 URL 或正式出处；
2. 首次发现、首次公开、本项目采集和任何更正／撤销时间，并说明缺失值与时区；
3. 来源许可、允许用途、版本、文件哈希和获取日期；
4. 置信度、证据等级、冲突合并与删失规则；
5. 地址到原始 locking script、`C_t`、`C_T` 和模型节点的可重放映射，含一对多、多对一及无法投影的分母；
6. 在不读取正式测试集的前提下冻结 `L_{<=t}` 构造、训练／验证 cutoff、未知与未标注处理，以及标签漂移敏感性。

若无法取得该证据包，S1 的最高可信范围保持为回顾性实体类型敏感性分析；S2 历史部署主张为 No-Go。
