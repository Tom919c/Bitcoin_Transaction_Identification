# 大创候选问题：最近邻与数据核验（第二轮）

日期：2026-08-31。范围：Gate 0–2的增量证据审计；未冻结方向、未训练模型、未开展用户实验。接续[首轮初筛](创新方向初筛-20260831.md)。本轮结果是排除不成立的创新表述、明确待验证问题，不是宣称已经找到获奖方案。

## 1. 用户修订与当前裁决

用户明确要求“工作量先不纳入考虑”。从本记录起，预计开发周期、团队投入和工程复杂度不进入候选评分，也不以“十月容易完成”偏向某个方向。前轮优先检查C/D/A是检索执行顺序，不是价值排名；其以降低筛选成本为由的优先级不再沿用。十月结题及2027年会仍是项目背景，具体实施分期留待之后讨论。

当前比较四件事：问题是否值得解决；相对最近邻改变了什么；数据和标签是否支持所说的任务；能否用可信评价证伪。**暂未取得数据不等于数据不可取得，更不等于方向永久淘汰。** 数据来源、许可、时间语义和独立参照仍需核验，这些不是可以用更多开发投入自动补齐的事实。

本轮尚不足以把C或D排在其他六类之前。它们的核验较深入，也暴露了较多已有工作；证据覆盖不均时不能把“查得更多”“已有代码”“容易演示”转换成方向优势。A/B/E/F/G/H继续保留，不能因需要更多调查、参与者或更大系统而降级。

## 3. 一个实际取得的数据快照：能支持什么，不能支持什么

来源：[Ransomwhere: A Crowdsourced Ransomware Payment Dataset](https://zenodo.org/records/13999026)，Jack Cable，版本1.1.0，发布2024-10-27，DOI `10.5281/zenodo.13999026`。本轮读取[Zenodo记录API](https://zenodo.org/api/records/13999026)，元数据声明许可为CC BY 4.0；这证明所下载文件的公开许可声明，不代表每条举报或归属标签已获得独立确认。

下载对象：[ransomwhere.json](https://zenodo.org/api/records/13999026/files/ransomwhere.json/content)，取得日期2026-08-31，仅保存到本机临时目录；不提交地址、交易或完整数据文件。

据此只能作以下判断：该快照提供公开地址、交易哈希和报告的家族标签，可用于寻找后续核查对象；仅凭该文件，E的文本—交易配对任务还没有输入，D的完整案件参照还没有成立，F的前瞻时间线也没有成立。补全链上交易可验证某些链上事实，但不能自动验证犯罪归属、举报真实性或资金实际控制人。`amount`及`time`的单位和生成方式还需来源/代码核验，本轮没有按其数值做收益或时间外推结论。

这是描述性字段审计，不是某个新方法的性能实验；没有产生模型优劣或统计显著性结论。

### 本机复核命令

使用现有环境，不同步或安装依赖。以下命令读取临时目录中已经下载的文件；文件缺失时应按上面的固定版本重新下载并先核对发布MD5，不得自动换成最新版。

```powershell
@'
import collections, hashlib, json, tempfile
from pathlib import Path
p = Path(tempfile.gettempdir(), 'innovation-ransomwhere-v1.1.0.json')
raw = p.read_bytes()
assert len(raw) == 5572091
assert hashlib.md5(raw).hexdigest() == '8a7bff74ab0dea4186232bc131c5d40f'
assert hashlib.sha256(raw).hexdigest() == '5c939f3f0d390813f78e649cdd5cd50dcac6ac286e8c9ba52206b273f761082d'
rows = json.loads(raw)
txs = [tx for row in rows for tx in row['transactions']]
counts = collections.Counter(tx['hash'] for tx in txs)
assert len(rows) == len({r['address'] for r in rows}) == 11178
assert len(txs) == 21790 and len(counts) == 18890
assert sum(v > 1 for v in counts.values()) == 412
assert sum(not r['transactions'] for r in rows) == 2938
assert all(set(r) == {'address', 'balance', 'blockchain', 'createdAt', 'transactions', 'updatedAt', 'family', 'balanceUSD'} for r in rows)
assert all(set(t) == {'hash', 'time', 'amount', 'amountUSD'} for t in txs)
assert all(r['blockchain'] == 'bitcoin' for r in rows)
print('Snapshot, counts and field sets verified; labels and time semantics NOT verified.')
'@ | uv --no-cache run --no-sync --offline python -
```

## 4. 从功能名称收敛到可以反驳的问题

以下为调查问题，不是已通过新颖性审核的方案，也没有赋予C/D更高排名。新的最近邻可以直接否定其创新表述；若改写问题，须另留决策记录。

| 候选问题 | 需要的参照与比较 | 否决或降级条件 |
|---|---|---|
| C1：对明确端点和查询语义，摘要是否会把“同类节点间有某条路径”误呈现为“这两个具体对象之间有路径”？能否减少这种答案错配并保持可用摘要？ | 精确定义地址/交易/实体单位；完整有限图上的枚举答案；Gsum等任务适配后的强基线；报告假答案、漏答案与摘要规模。真实归属标签不得由该图路径反推。 | 已有方法在等价语义下已解决，或正确适配基线后优势消失，不能保留该新颖性表述；不存在实际错配则问题动机需要重证。 |
| C2：在有明确停止边界的局部查询中，能否准确区分“已找到答案”“已证实边界内无答案”“证据不足”，并给出可复核的查询完成状态？ | 完整有限图作算法参照，另构造/选取不完整上下文；与双向展开及已有不完整图查询方法比较。必须检索数据库确定答案、查询完整性等最近邻。 | 仅把普通搜索状态换名称、已有查询完整性机制已等价覆盖，或把未访问图外的未知误称不存在，不能称为新方法。 |
| D1：来源标签被撤回或聚类假设改变后，系统能否准确指出哪些既有结论需要重查、哪些仍由直接事实支持？ | 明确依赖规则、记录版本和已知变更事件；独立人工/规则参照；与现有证据溯源和增量依赖分析比较。公开案例只支持它实际公开的事实。 | 泛用溯源系统已完整解决、只能追踪链接而不能正确界定受影响结论，或用系统自己的输出作真值，则不能支持增量贡献。 |
| D2：在结论允许“不足以判断”的任务中，证据呈现能否减少将实体类型、启发式路径或举报误认为定罪事实的错误？ | 具有明确可知边界的任务材料；区块浏览器/现有工具等对照；区分客观答题正确性与真实使用者研究，后者另遵守伦理和参与授权。 | 只有满意度、演示成功率或模型自评，不能声称减少真实用户误判；若差异来自题目提示而非方法，也须降级。 |

如果主张无损保真，一条违反保证的反例就足以否定该保证；如果主张有损摘要的权衡，漏掉一个答案本身并不自动否决整个方向，必须依据事先规定的假答案/漏答案/规模指标比较。不能在看完结果后更换评价口径。

A/B/E/F/G/H下一步也需达到这种具体程度，再开展同标准比较。缺少人员或尚未完成某个数据获取步骤只记为待核验输入，不以工作量为由移入放弃清单。新问题可以替换旧八簇，不要求为了保持表格而继续不成立的表述。

## 5. 历史资产复用与证据边界

本轮阅读了既有重新选题目录的`n1-flow-certificate-pilot.md`、`gate2-reentry.md`及前瞻归属方向的代码/数据审计记录。它们提示：旧实体聚合图与原始UTXO/地址身份之间存在映射缺口；历史资金质量证书方案存在与标准运输/流问题重合的风险。原始记录的失败与负结果应保留，但本轮没有重新运行其试验，也不把旧方向的No-Go直接推广为所有大创系统方向均不可行。

当前本机确实存在若干处理后的协议子图；检查PATH未找到`bitcoin-cli`或`bitcoind`，这只说明命令未在PATH中，不证明机器上没有节点或其他数据。没有把这一点作为方向排名或放弃理由。

已有前端仍只是实现资产；示意路径、代理分数和生成解释不能升级为本轮数据证据。即使不考虑工作量，也不应在主问题确认前将多个尚未通过核验的方向拼装成平台。

## 7. 独立反方审查与整合

实际调用`gpt-5.6-terra`对固定证据摘要进行只读逻辑审查，输入明确排除工作量排序，要求指出C/D是否有足够证据领先其他簇。它没有重新读取全文，不能记作第二次独立来源核验。其结论支持：现阶段不足以确定C/D领先；近似摘要的漏失应按预先定义的权衡评价；完整案件真值不能由Watch Your Back的局部关系参照替代。主负责人对照E07–E09后采纳这些限制。

审查还提出“摘要误差与下游调查收益的关联”等问题。这里不直接纳入已认可方案：外部地址标签即使存在，也未必能定义案件收益，Ransomwhere不能自动承担这种真值。其“有司法或执法材料即可评价证据分层”的建议也需收紧：材料必须逐项对应要评价的主张，且本身可能不完整。第4节是主负责人据核验结果形成的进一步问题草案，不声称每条都已通过子审查或证明原创。
