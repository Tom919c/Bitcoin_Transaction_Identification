# AWS 公共比特币数据源资格审计

日期：2026-09-10（清单快照主要采集于 2026-09-09 UTC）

状态：**待资格化候选**。匿名访问与关键字段的样本级可恢复性已核验；数据许可适用范围、不可变快照、全量主链／prevout 完整性、金额转换和本机资源门仍未关闭。本记录不选择该源，不关闭 Gate 3A 数据硬门，不授权 S0。

## 1. 审计问题与停止线

本轮只回答五个问题：公开入口能否无账户读取；是否从 Bitcoin 创世期覆盖到近期；Parquet 是否实际提供 S0 所需字段；对象能否形成可复查快照；当前资源能否完成冻结范围。未计算 `p_merge`、`p_rewrite`，未读取标签、最终 alias 或模型结果。

若来源不能恢复唯一主链、区块内交易顺序、parent outpoint、parent output 原始 locking script 或 coinbase 标记，则数据源直接 No-Go。若字段可恢复但许可、快照或资源未关闭，则只保留为候选，不以样本成功代替全量资格。

## 3. 匿名对象清单与规模

使用 S3 `ListObjectsV2` 匿名接口，按 `v1.0/btc/blocks/` 与 `v1.0/btc/transactions/` 分页读取对象元数据。2026-09-09 约 15:37 UTC 的清单快照如下：

| 前缀 | 对象数 | 总字节数 | GiB | 首对象日期 | 清单末端 |
|---|---:|---:|---:|---|---|
| `blocks/` | 6,560 | 345,172,218 | 0.321 | 2009-01-03 | 2026-09-09 区块 966231 |
| `transactions/` | 6,560 | 2,176,300,740,057 | 2,026.838 | 2009-01-03 | 2026-09-09 区块 966231 |

2026-09-09 是当时仍在增长的 UTC 当前分区：稍后的复查已出现区块 966232。这说明“每日更新”不能被解释为查询时点固定。正式 manifest 必须排除未完成日，并在一次一致清单上冻结对象键、长度、服务端 checksum、访问时间和导出哈希。

### 3.1 50 GiB 早期前缀预检

2026-09-10 完成一次首次成功的网络预检（Python 3.12.3、PyArrow 16.1.0、非 `uv`、4 workers）。在 50 GiB（53,687,091,200 字节）压缩 S3 transaction 对象字节上限下，6575 个 transaction objects 中纳入 1890 个、共 53,659,133,189 字节，最后完整纳入日为 2014-03-12；为识别日边界后的首个高度，预检额外读取至 2014-03-19 的区块元数据，共 1897 个 block objects、90,449,066 字节、291390 行。高度唯一且连续为 0..291389，重复高度、prevhash break 和边界日后误入候选前缀均为 0；边界日后最低高度为 290292，候选 `h_max=290291`，tip hash 为 `00000000000000001296ee1fb5fdbbcf95f0519ad8c40c07414617d70dc16a38`。

在 `h_max-52560=237731` 之前，非 coinbase 累计量为 18,131,019；20/40/60/80% 首次达到高度为 `[183399, 200724, 216332, 227188]`，向下对齐 2016 后为 `[181440, 199584, 215712, 225792]`。一个不调用主预检计算函数的独立只读实现，从 1897 个缓存 Parquet 重算了高度、prevhash、日期、总量、分位、对齐和 tip，结果全部一致；两条路径都未读取效应指标。该结果只是候选资源边界，结论限于早期历史，不能关闭许可、不可回溯快照、transaction payload/金额/prevout、完整 source provenance mapping 或 S0 硬门。成功执行前未冻结临时脚本哈希，而脚本随后为失败恢复和边界输出修改；当前哈希不能冒充实际执行 revision，这是额外的可追溯性 P1。详情见 [结构化结果](AWS-50GiB前缀预检结果-20260910.json)。

按清单中的原始 transaction 对象字节累计，25 GiB 首次越过于 2013-06-01，50 GiB 于 2014-03-13，100 GiB 于 2015-03-09，500 GiB 于 2018-01-31，1,000 GiB 于 2021-02-22，1,500 GiB 于 2023-12-03，2,000 GiB 于 2026-07-19。这些阈值只用于资源预检，不是研究 cutoff，也不得依据未来效应选择范围。

本机 2026-09-10 只读快照中，`D:` 可用 139,442,827,264 字节（约 129.9 GiB），物理内存 29,734,326,272 字节（约 27.7 GiB）。因此，约 2.0 TiB 的完整 transaction 对象本地副本对当前机器明确 No-Go；流式或列裁剪不等于资源已通过，仍需预先登记网络读取量、派生数据体积、并查集表示、失败恢复和校验成本。

## 4. 对象版本与字节完整性

匿名 `GET ?versioning` 返回空的 `VersioningConfiguration`；样本 `ListObjectVersions` 返回 `VersionId=null`。2009 年对象的 `Last-Modified` 为 2026-02-18，符合历史数据曾被重新生成或替换的可能性。公开桶因此不能提供“以后按 `VersionId` 重取同一 vintage”的保证。

这不否定一次性冻结导出的可能性。对 2009-01-12 transaction 样本，带 `x-amz-checksum-mode: ENABLED` 的 HEAD 返回 `FULL_OBJECT` SHA-256：

```text
DiOBSkZ/HByHGBO/LbL+MRoUBv3ysnSDHsmAkX6qta4=
```

其本地十六进制 SHA-256 为 `0E23814A467F1C1C871813BF2DB2FE311A1406FDF2B274831EC980917EAAB5AE`，Base64 后与服务端值一致。该结果只证明这一次读取的单对象字节一致；它不证明全量对象跨时点一致，也不替代本地冻结导出与完整 manifest。

## 5. 样本级 schema 与语义核验

临时样本仅用于资格审计，未进入仓库和实验登记：

| 样本 | 字节数 | 本地 SHA-256 |
|---|---:|---|
| 2009-01-03 blocks | 7,541 | `CFD11AA178D920E9DB64C723AF48A711C3ED613C64C7459F5138BDC73968407C` |
| 2009-01-03 transactions | 10,128 | `D95D972E20B6A347234F6D2A4B5E035B7072930527F41912C02EC713B6B43431` |
| 2009-01-12 blocks | 28,095 | `D7ED914F61CCA1D9F511F0034A1E02C4256A1DFCD3814127EB138F5AAE6DC209` |
| 2009-01-12 transactions | 63,684 | `0E23814A467F1C1C871813BF2DB2FE311A1406FDF2B274831EC980917EAAB5AE` |
| 2026-09-09 block 966125 transactions | 4,537,325 | `0A252DDCAB94DCDAA345241160D3E3F065665CDFA8429CEF6899F37BC5132B96` |

使用 Python 3.12.3、PyArrow 16.1.0 只读检查物理 schema 和行内容，得到：

1. block 文件实际含 `hash`、`number`、`transaction_count`、`previousblockhash` 和 `chainwork`。同一日文件中的行不按高度排序，适配器必须按高度和后续交易 index 显式排序，不能继承文件顺序。
2. transaction 文件实际含 `txid`、witness `hash`、`block_hash`、`block_number`、块内 `index`、`is_coinbase`、input 的 `spent_transaction_hash/spent_output_index`，以及 output 的 `index/script_hex/value`。现代样本 3,981 笔交易中有 3,806 笔 `txid != hash`；parent outpoint 必须使用 `txid` 语义，不能混用 witness hash。
3. 2009-01-12 样本中，子交易 `4385...cd79` 的 input 能以 `(12b5...91ba, 0)` 唯一连接到同一快照内区块 183 的父输出；父输出 locking script 为原始 `script_hex`。input 自身 `script_hex` 是 scriptSig，不能替代 parent output locking script。
4. 现代样本交易 `ce03...8c04` 的 `txid`、区块 966125、block hash、首 input prevout 和首 output locking script 与 2026-09-09 查询的 Blockstream API 返回一致。这是一个独立样本交叉核验，不是全量主链证明。
5. 实际 Parquet 存在 schema 漂移：创世 transaction 文件因只有 coinbase 而没有 `inputs` 字段，后期文件增加 address/witness 子字段；正式适配器必须以所需 leaf allow-list 建立兼容 schema，并对缺失必需字段显式失败。

### 5.1 金额的 `double` 边界

AWS 文档与实际 Parquet 都把 BTC 金额存为 IEEE 754 `double`，不能直接当作精确金额。对 2009-01-12 的 228 个金额值，`abs(value * 1e8 - round(value * 1e8))` 最大为 0；对区块 966125 的 31,926 个 transaction/input/output 金额值，最大为 `0.000244140625` 聪，24 个值大于 `1e-6` 聪，但均远低于半聪。

这只支持预注册一个候选恢复规则：对有限、非负 BTC 值计算 `s = round(value * 1e8)`，同时记录残差并要求其严格小于冻结阈值；随后以整数聪执行范围、输入输出守恒和过滤器计算。阈值必须在读取全量效应前冻结；任何越界、非有限值或守恒失败均阻断，不得静默取整。

## 6. 许可边界

Open Data Registry 的字段规范把 `License` 定义为“dataset license 或数据使用条款”的说明或链接；本数据集条目在该字段链接到 AWS 说明仓库的 MIT-0 文件。然而，链接文件的许可对象写作 “this software and associated documentation files”，analytics README 也写作 “this library”。因此可以核验的是：Registry 为该数据集记录提供了 MIT-0 链接；当前证据不足以单独确认 S3 Parquet 对象的长期保存、再分发和公开研究 artifact 权利。

AWS Open Data Sponsorship Program 当前条款要求参与者以无需付费的宽松许可提供 Program Content；但该一般条款不能代替本数据对象的明确许可解释，也不能由本项目自行决定其回溯适用。正式冻结前需要人工确认保存、派生、论文复现与公开 artifact 的许可范围；在此之前只允许内部资格审计。

## 7. 资格结论与后续条件

证据状态：

- `source-verified`：公开路径、匿名读取、AWS 维护声明、experimental 声明、文档 schema、清单时点与对象规模、未启用 S3 Versioning，且样本 `VersionId=null`、样本服务端 SHA-256。
- `interpretation-verified`：指定样本中的 parent-output join、`txid/hash` 区分、locking script 和 Blockstream 交叉核验。
- `pending`：数据许可适用、选定范围内由项目控制且可复查的不可变冻结导出、全量唯一主链与 prevout 完整性、金额转换全量审计、资源预算和 S0 输入资格。

AWS 候选只有在以下条件全部关闭后才能成为 Gate 3A 数据源：

1. 人工确认数据对象的保存、派生和公开 artifact 权利。
2. 在读取任何效应前选择完整且已结束的 UTC 日边界，冻结对象清单、逐对象本地 SHA-256、schema hash、tip height/hash、适配器 revision 和访问时间，并记录可获得的服务端 checksum 及其算法；公开桶未启用 S3 Versioning 时，必须保留由项目控制且可复查的不可变冻结导出，位置可以是本地或经授权的存储。
3. 从创世块到冻结 `T` 全量验证高度／prevhash 连续、唯一主链、每区块唯一交易位置、coinbase、parent outpoint 唯一存在、parent output locking script 可恢复，以及 missing/orphan/reorg/duplicate 计数。
4. 冻结整数聪转换与拒绝阈值，并全量通过残差、范围和价值守恒检查。
5. 冻结资源上限、流式读取／恢复策略和派生产物空间；不能把约 2 TiB 的公共可访问性写成本机可执行性。
6. 对 tip 和冻结的分层样本使用独立节点或区块来源交叉核验。

若采用“早期完整前缀”控制资源，必须在看到任何 `p_merge/p_rewrite` 前另行预注册一个仅由资源上限决定的末端规则，并从创世块完整处理到每个 `T_j`；它只能支持该历史范围的结论，不能冒充当前时期或全链结果。若采用云查询，则仍需人工批准账户、费用、不可变导出和完整性方案。

独立反方审查未发现 P0；四项 P1 是数据对象许可未闭环、公开桶不构成可回溯历史快照、缓存名缺少 S3 key/listing revision 的可逆映射而不能证明正式 source provenance 或 selected set，以及成功执行脚本的实际 revision 未在运行前冻结。最终决定保持：**候选保留，Gate 3A v0.1 不冻结，S0 不启动。**
