# C1预注册协议草案：严格按时可见、延迟揭示的比特币关联标签可靠性

日期：2026-09-01

状态：**讨论稿，未冻结，等待用户确认主方向**

阶段：Gate 2完成后的Gate 3A准备

权限边界：本稿不授权训练新模型、查看最终测试结果或宣称创新已证实。

## 1. 研究问题与交付边界

主问题是：在目标交易被区块确认、按块内顺序处理到该交易时只能使用此前可见的链上信息，而输出关联标签可能在未来共同花费后才揭示的情况下，静态完整快照评测高估了多少对未来启发式关联标签的预测能力；显式记录标签延迟、右删失与拒判，能否改善固定观察窗内可揭示样本的未来时期预测？本任务不代表广播时刻或mempool实时决策。

项目研究的是受限链上关联证据。多输入启发式产生的连接不能解释为自然人身份、受益所有权、非法活动、欺诈或AML风险。既有0至10实体类型标签和`-1`未标注节点不参与生成C1标签。

预期交付包含四层：

1. 可重放的标签揭示时间构建器和数据manifest；
2. 静态hindsight、严格as-of和删失感知评测协议；
3. 强规则／tabular／选择性预测基线及必要方法；
4. 展示标签何时可知、哪些特征越界、模型在何处拒判的可视化系统。

若方法没有超过强基线，但发现稳定且有实际量级的hindsight膨胀，项目可降级为数据／评测贡献；若连hindsight差异也很小，则停止C1研究主张并返回Gate 2。任何主张和图表都必须使用“未来启发式关联标签”或等价限定，不得把代理目标缩写为真实找零、钱包控制权或身份真值。

## 2. 对象、事件和符号

目标单位是一个具有两个可花费输出的Bitcoin交易。目标时刻`T_i`使用`(block_height, transaction_index)`表示；同一区块中位于目标交易之后的记录属于未来信息。

- `X_i`：目标交易本身及`T_i`之前可见的特征；
- `Y_i`：在过滤后的动态多输入关系中，首先且唯一与目标输入分量连通的输出索引；
- `D_i`：从`T_i`到该连通事件的延迟；
- `C_i`：从`T_i`到固定观察快照末端的最大可观察延迟；
- `R_i = 1[D_i <= C_i]`：标签是否在快照内被揭示。

事件原因至少分为：输出0首先连接、输出1首先连接、两输出同事件／无法排序的歧义连接、观察结束仍未连接。歧义事件不能强制二元化；未连接是右删失，不能当负类或“没有找零”。

主分类estimand是固定目标时期、固定观察窗口内可揭示样本上，严格as-of特征对“哪个输出后来首先形成受限链上关联”的条件预测风险和选择性覆盖。辅助estimand是不同输出原因的揭示时间／累计发生概率。两者都不等于真实钱包控制权。对全部目标交易的总体风险只有在可核验的选择机制假设下才报告点估计；否则只报告未测选择敏感性或部分识别界。

## 3. 数据快照与许可

第一阶段使用两个版本化快照：

- 复现快照：Bitcoin主链截至区块`689256`，对齐Möser与Narayanan论文的2021年6月数据边界；
- 扩展快照：用户确认后取得的固定主链高度和区块哈希，用于增加后续钱包时期与延长随访。

原始数据优先顺序是自有Bitcoin Core／BlockSci只读快照、官方可核验公共数据接口、Google BigQuery公开`crypto_bitcoin`。当前252M PostgreSQL只有聚合节点／边表，缺txid、outpoint、脚本和块内顺序，不能作为C1主数据源。

每个快照记录：来源、许可、访问日期、链高度、tip hash、文件hash、schema、行数、异常交易处理和生成revision。公开CSV `change-ground-truth.csv`只用于复现标签索引与抽样核对，不能替代完整链事件。

## 4. 标签揭示时间重建

按主链顺序处理交易，在加入当前交易关系前保存as-of状态。对通过过滤的多输入交易，把其输入脚本标识加入同一动态连通分量。脚本标识须覆盖P2PK、P2PKH、P2SH、SegWit及可解析类型；不得因缺少传统地址字符串丢弃P2PK。

对每个目标交易，揭示时间是某一候选输出脚本与目标交易任一输入脚本首次进入同一连通分量的事件。只看标签输出的首次花费高度不充分：前8条抽查中4条没有在首次花费交易里直接出现原输入脚本，且1条在同一区块稍后花费。

批量实现可使用带合并时间的并查集重构树或等价的离线动态连通算法。该算法是计算工具，不作为原创理论主张。必须保存可审计的最小证据路径：目标交易、候选输出、产生连接的交易、前后分量标识、块高和块内位置。

CoinJoin、Payjoin及其他协作输入会破坏多输入启发式。Gate 3A v1.0必须固定可复现的排除规则和规则版本，并报告：排除比例、无法判定比例、规则敏感性，以及不排除／保守排除下结论是否改变。不能把检测器自己的CoinJoin规则输出当独立身份真值。

## 5. 信息截止与禁止特征

允许特征只能来自目标交易及此前历史，例如目标交易金额、脚本类型、输入／输出计数、目标时刻之前的地址新鲜度、历史脚本组合和过去钱包指纹。

主实验禁止：输出后来是否花费、花费时间、花费交易特征、最终全链聚类、最终地址年龄、测试时期统计量、观察快照末端才能知道的余额或标签，以及任何由测试标签聚合得到的特征。

所有标准化、缺失值处理、类别编码、特征选择、校准和阈值只在训练／验证期拟合。静态hindsight特征可以作为诊断oracle，用于量化高估来源，但不进入可部署方法排名。

## 6. 切分与四级对照

主切分按目标交易时间形成训练、验证、最终测试三个连续时期；具体块高边界必须在用户确认后的分布审计中一次冻结，只能依据交易量、事件／删失支持和协议时代选择，不能依据模型成绩选择。

另设“未来新分量”测试：使用训练截止时的动态输入分量定义组别，测试在训练期未出现的分量。最终全链分量不能用于分组，因为它包含未来关系。

四级对照用于分解高估来源：

1. `H0`：论文式静态完整快照、随机切分与未来指纹，作为hindsight oracle；
2. `H1`：严格as-of特征但仍随机切分，隔离未来特征影响；
3. `H2`：严格as-of特征、时间切分、仅完整案例，暴露标签选择偏差；
4. `H3`：严格as-of特征、时间切分、显式右删失／拒判，为候选部署协议。

H0只用于诊断，不得在项目结论中称为未来部署性能。

## 7. 假设与可证伪结论

- `H-A`：H0相对H1／H2存在非平凡的hindsight性能膨胀；
- `H-B`：标签揭示概率依赖目标时刻可见的钱包／交易特征，完整案例不是部署总体的随机样本；
- `H-C`：在训练期估计的揭示机制和拒判策略，能在未来时期改善校准或固定错误预算下的有效覆盖；
- `H-D`：上述结论在保守CoinJoin排除、不同观察窗口和新分量测试下方向一致。

令完整案例分布为`P(X,Y | R=1)`。只有在`Y`与`R`给定`X`后条件独立，且每类样本有正的揭示概率时，基于揭示概率的加权才能识别总体风险。该条件不可由公式自动保证；协议必须检查权重重尾、positivity和未测选择敏感性。若条件明显不成立，只保留固定快照内可揭示样本的条件风险与有界敏感性分析，不宣称已校正总体风险；若合理敏感性参数使核心结论方向翻转，则停止“改善未来总体可靠性”的主张。

## 8. 基线与方法升级顺序

先运行低成本基线：

1. 单个确定性找零启发式和论文的阈值投票；
2. 仅目标交易特征的逻辑回归／随机森林；
3. 严格as-of的论文特征复现；
4. 时间更新但不处理删失的完整案例模型；
5. 训练期Kaplan–Meier／非参数累计发生作为揭示时间参照；
6. 简单揭示概率加权、分层或拒判策略。

只有基线证明核心偏差存在且简单修正不饱和，才进入生存森林、梯度提升、图模型或新方法。不得为了沿用旧资产而优先上GNN。scikit-survival仅是候选实现工具；依赖不在Gate 3A前安装。

若把输出0／输出1视为竞争事件，应报告原因特异累计发生概率；把另一输出事件简单当普通删失不能解释为该输出的绝对概率。标准`1-KM`也不能替代竞争风险CIF。

## 9. 指标、统计单位与不确定性

主要分类报告错误—覆盖曲线、固定低错误预算下的覆盖、precision／FPR及拒判比例。原论文使用低FPR场景，因此首选决策比较是“在预先冻结的FPR上限下覆盖多少交易”，而不是单独最大化accuracy或F1。

揭示时间辅助报告：事件／删失比例、揭示延迟分布、原因特异累计发生、Uno IPCW concordance、预先指定时点的动态AUC、Brier／IBS及独立校准检查。IPCW的删失分布只能从训练数据估计；评测时点必须落在训练随访支持内且删失生存概率为正。Harrell C只表示排序，不表示校准。

统计独立性不按随机交易行假设。区间估计至少按目标时间块和目标时刻输入分量做聚簇重采样；seed波动与数据抽样不确定性分别报告。所有学习模型至少5个预注册种子，确定性规则不伪造seed方差。

## 10. Pilot阶段与停止线草案

### Pilot A：重建正确性

- 从公开CSV按年代、脚本类型和输入规模分层抽取至少1000条；
- 复现输出索引，恢复最早连接事件和证据路径；
- 对不一致、歧义、同区块连接和疑似协作交易逐类审计。

建议停止线：输出索引复现低于99%，或确定性揭示时间无法恢复的比例超过5%，则停止建模并修复定义；若无法形成唯一、可审计的标签语义，则C1 No-Go。保守与宽松协作交易过滤必须分别复跑；若两套规则使核心差异方向翻转，C1研究主张No-Go。

### Pilot B：偏差是否存在

在开发时期比较H0至H2，先跑规则、逻辑回归和随机森林。建议实质门槛为：H0相对严格协议在固定FPR覆盖上至少相差5个百分点，或在匹配覆盖下错误率至少扩大／缩小2倍，并且聚簇置信区间排除预先定义的无实际差异区间。最终数值须在只看开发数据的功效／效用审计后、打开测试集前冻结。

### Pilot C：简单修正是否饱和

比较完整案例、分层、加权和拒判。若简单as-of规则已经达到预设低错误预算，或删失修正对未来期没有稳定增益，则不开发复杂模型。若偏差存在但无法在可接受假设下校正，保留评测／数据贡献并降低方法主张。

### 三选一决策

- `Go`：标签链可重放，偏差有实际量级，且至少有数据／评测或方法贡献未被强基线解释；
- `Stop`：标签语义不稳、未来信息影响很小、强规则饱和或最近邻等价覆盖；
- `Return Gate 2`：出现新的数据或最近邻证据，需要在M1、P2、Payjoin中重新排序。

## 11. 测试集打开和实验登记

最终测试manifest在任何模型选择前冻结。测试结果只允许协议规定的一次主打开；每次额外打开记录日期、原因、commit和决策。Pilot前在`experiments/experiment_registry.csv`登记问题、协议版本、数据hash、split、cutoff、模型、seed、预算、指标和停止条件。

每个结果保存代码revision、dirty状态、数据manifest、配置、环境、硬件、日志、原始预测和表图生成入口。环境继续以仓库`uv`、`pyproject.toml`和`uv.lock`为依赖真源；旧Conda环境只用于迁移前复现。

## 12. 伦理与表述

公开链上数据不等于可以无约束指控现实主体。展示只显示交易结构、时间可见性和启发式置信，不展示未经核验的真实姓名或违法判断。输出措辞使用“链上关联证据”“启发式揭示”“可能的找零输出”“拒判”，不用“识别罪犯”“确定同一自然人”或“AML风险真值”。

## 13. Gate 3A冻结前必须关闭的事项

1. 用户明确确认C1为主方向，并取得正式任务书／申报书核对允许的技术路线偏移；
2. 固定复现与扩展链快照、获取路线、许可和manifest格式；
3. 固定CoinJoin／Payjoin排除规则及脚本标识单位；
4. 用分布审计确定时间边界、评测时点和各时期事件／删失支持；
5. 在开发数据上完成数值停止线的功效／实际效用审计；
6. 明确正式题名和行政口径，措辞不把C1写成非法交易识别、真实找零或实时mempool决策。

以上事项全部关闭后，本稿才能升级为`Gate3A-C1-v1.0`。任何未填项都不能用训练结果倒推补写。

## 14. 最近邻反证快照

2022至2026补查已合入创新性台账。直接前作Möser与Narayanan已经覆盖“未来多输入关系揭示过去找零”以及启发式随时间变化，故C1不能把未来揭示本身称为创新。Kappos等覆盖簇生命周期和私有服务真值，Ghost Clusters说明商业归因采用会随时间变化的当前快照；这些工作抬高了真值和时间审计门槛。

其余邻近工作分别研究未确认交易提供的实时信息、聚类率随时间变化、静态多启发式规则、仿真真值和带时间戳的交易图数据。本轮没有发现其中任何一项同时记录逐例`T_i`与揭示时刻、将未揭示样本作为行政右删失、只使用`T_i`前特征并做未来时期测试。这个检索结论只支持进入Pilot，不能写成“全球首次”。

最强反证条件保持不变：如果完整工件后续发现已有逐例reveal transaction／time和固定窗口删失评测，C1的新任务差异会被直接削弱；如果只在已揭示子集上计算分类指标，C1仍然只是Möser随机切分的时间版，不能晋级。
