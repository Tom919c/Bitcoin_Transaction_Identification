# 面向国际顶会的比特币交易图研究候选路线评估

## 现有结果真正揭示了什么问题

你当前的实验已经不只是“EGS 比 GraphSAGE 更强”这么简单了。它实际上暴露出一个很有研究价值的复合难题：在主协议 `class_balanced_khop` 上，EGS 的 multi-seed Macro-F1 达到 0.6505±0.0138，显著高于 GraphSAGE 的 0.5785±0.0095；但到了 `temporal_balanced`，EGS 只有 0.2565，绝对性能仍然很低。与此同时，协议诊断显示大多数类别的同类邻居占比不足 15%，入边未标注邻居占比高达 77%–95%，而 MIXER 的同类邻居占比只有 0.4%。这说明你遇到的不是单一“长尾分类”问题，而是**时间分布漂移、异配、有向资金流、未标注邻居主导和类别极不均衡共同作用**的失效机制。fileciteturn0file0

这类现象本身就很接近值得发论文的问题。近年的图学习文献已经反复说明，异配图上 GNN 的成败不能只看“同质性高不高”，而要同时看邻域分布、平均度、拓扑噪声以及模型到底在聚合什么信息；其中一些工作明确指出，分离聚合、去混合、方向性感知和对真正困难异配数据的严谨评估，往往比单纯堆更复杂的网络更关键。citeturn23view4turn23view5turn23view6turn24view0turn24view3

所以，当前结果最值得珍惜的地方，不是你已经有了一个“分数不错的模型”，而是你已经观察到一个**科学上可以被正式定义的问题**：在大规模、方向敏感、标签稀缺、强异配的比特币实体图上，随机分层下有效的图消息传递，在时间外推下会明显失灵；而方向分离确实能显著缓解这一问题，但尚未真正解决。这个现象与最新文献中对 temporal graph benchmark、heterophily evaluation、graph OOD generalization 的关切是同频的。fileciteturn0file0 citeturn20view0turn24view0turn25view0turn25view3

## 外部文献扫描后最明显的研究空白

近两年的 temporal graph 方向，一个重要趋势是“**benchmark 与 realistic evaluation 本身就是研究贡献**”。TGB 明确把重点放在更真实、更可复现、更困难的时间图评估上，并指出大规模节点级 temporal 任务仍然稀缺，而且在动态节点属性任务上，简单方法经常能打败更复杂的 temporal GNN。TGB 2.0 进一步说明，大规模 temporal/heterogeneous graph 的标准化评测仍不足，边类型信息十分关键，而且很多复杂方法在大图上根本跑不动。citeturn20view0turn17academia2

异配图学习文献的趋势也很一致：一方面，Dir-GNN 这类工作证明，在异配设定下，把图当成有向图处理并分别聚合入边和出边，确实能提高“有效同质性”，并显著优于把方向丢掉的常规 MPNN。另一方面，最新再评估工作又提醒大家，异配论文极容易因为调参不充分、数据集不够难、评测不够严谨而夸大贡献。换句话说，**方向性是机会，但仅凭“我加了方向所以涨了”还不够，必须把评估做成别人无法轻易质疑的样子**。citeturn21view0turn21view1turn24view0turn24view3

再看 graph OOD/generalization 方向，近年的代表性工作已经把重点从“做一个更强 GNN”转到了“**为什么图模型会在分布漂移下失效**”。WWW 2024 的因果干预路线把问题解释成环境带来的潜在混杂偏差；TAR 则强调不应过度依赖理想化不变量假设，而是通过 topology-aware reweighting 去获得 distributional robustness；DeCaf 进一步把 feature-label 和 structure-label 两条机制显式分开学习。你的 `temporal_balanced` 正好天然提供了一个真实的时间环境变化场景，这与这些文献的核心问题非常贴近。citeturn25view0turn25view1turn25view2turn25view3

在加密货币 AML 方向，已有研究大多集中在 Elliptic 或 Elliptic++ 上，既有 transaction-level 任务，也有 illicit address/account detection；也有工作开始重视有向多重边、边属性序列和多图建模。与此同时，2024 年之后出现的两个比特币大图数据方向——一个是 2.52 亿节点、7.85 亿边、带实体类型标签的 Bitcoin Research 数据集，另一个是 ORBITAAL 这样的 entity-entity temporal graph 数据集——说明社区正在转向**更大规模、更实体级、更时间化**的 Bitcoin 图研究。可问题在于，当前公开文献里，对“**实体级多类别时间外推节点分类**”这一问题的系统研究仍然不充分，特别是把时间漂移、异配、方向和风险排序放在一起讨论的工作很少。citeturn21view4turn21view5turn21view6turn21view7turn5academia0

这正是你最有机会切进去的空白：不是再做一个普通的 AML 分类器，而是把这个问题正式表述成**directed temporal entity graph 上的 heterophily-aware OOD risk identification**。从文献地图看，这个交叉点目前并不拥挤。citeturn22view0turn25view0turn21view0turn21view7

## 候选研究路线池

基于现有结果和文献，不应该直接固定唯一主线，但可以形成一个更严格的候选路线池。下面这四条路，都有研究价值，只是上限、风险和对你当前资产的匹配度不同。这个表格是对当前项目与外部文献的综合判断，不是既定结论。fileciteturn0file0 citeturn20view0turn24view0turn25view0turn21view4

| 候选路线 | 核心问题 | 与当前资产匹配度 | 新增数据需求 | 风险 | 顶会潜力 |
|---|---|---:|---:|---:|---:|
| 新基准与机制分析 | 把问题定义为“时间外推下的实体级风险识别 benchmark”，发布协议、诊断、挑战分类 | 很高 | 低到中 | 低 | 中高 |
| 时间 OOD 方法路线 | 把 `temporal_balanced` 视为 graph OOD，做因果解耦/环境重加权/时间鲁棒聚合 | 很高 | 低 | 中高 | 很高 |
| 开放世界与风险发现 | 从闭集 11 类分类扩展到 open-world / PU / ranking 导向的风险发现 | 中高 | 中 | 高 | 中高 |
| 子图与行为模式路线 | 用 motif / local flow pattern / node-subgraph 联合学习去解决 MIXER、EXCHANGE 等混淆 | 中 | 中到高 | 很高 | 高 |

第一条路线的优势是稳。TGB 一类工作已经表明，只要 benchmark 足够真实、规模够大、评估协议清楚、代码和 leaderboard 可复现，**新基准本身就可以成为贡献**；而你的项目已经具备协议对照、时间 split、敏感实体 ranking、case study 和方向消融这些很像 benchmark paper 的骨架。其问题在于，如果没有公开释放协议、加载器、强 baseline 和可重复 leaderboards，这条路的上限会明显下降。citeturn20view0turn17academia2turn21view4turn21view5

第二条路线的上限最高，也最契合你现在的实验症状。你的 EGS 已经证明方向分离对主协议有用，而 temporal 仍然很差；文献里又已经出现 temporal heterophily、graph OOD 和 causal decoupling 这些相邻问题，但还没有在比特币实体风险识别上形成一个很强的统一答案。若你能把问题收束为“**为什么 directed temporal risk graph 上会出现结构-特征-时间的复合漂移，以及怎样用方向感知与因果解耦 jointly 处理**”，这是最接近顶会方法线的。fileciteturn0file0 citeturn22view0turn21view0turn25view0turn25view2turn25view3

第三条路线的价值在于更贴近真实 AML：现实里绝大多数节点是未标注的，未知风险类型会不断出现，人工审查也更关心 ranking 而不是闭集精度。图学习里已经出现 open-world SSL、novel class discovery 和 PU node classification 这类工作，说明“已知类 + 未知类 + 未标注数据”的设定本身是有论文价值的。问题在于，你当前数据的未标注节点在项目定义中更多是背景上下文，而不一定天然等价于“未知新类”，因此如果要走这条路，必须非常谨慎地重写任务，避免概念偷换。citeturn21view8turn10academia1turn10academia3turn23view0turn23view1

第四条路线是典型的高风险高收益路线。现在 MIXER 大量被判成 EXCHANGE，本身就提示单点节点表征可能不足；而加密货币异常检测文献也确实有通过 directed multi-graph、parallel edges、sequence pattern 和多图视角刻画洗钱模式的研究。若能证明某些类别本质上不是 node label，而是 local flow motif label，那么“节点分类失效边界 + 节点-子图联合学习”会非常有新意。但它的风险在于：一旦没有明确的 motif 监督、没有稳定的弱标签构造，工作量会迅速膨胀，且失败成本很高。fileciteturn0file0 citeturn21view7turn6academia3

## 哪些方向更有可能形成突破性贡献

如果目标真的是冲国际顶会，仅靠“把 EGS 再改复杂一点”通常不够。近几年的高影响图学习论文，真正有说服力的增量一般来自三类东西：更难而且更真实的 benchmark、更能解释失败原因的机制分析、以及对核心困难设定有明确针对性的训练/推断原则。你现在最接近的“突破点”，其实不是模型结构本身，而是**把当前现象抽象成一个尚未被充分定义的科学问题**。citeturn20view0turn24view0turn25view0turn25view3

我认为最有创新上限的定义是这样的：**比特币实体风险识别不是普通的静态多类节点分类，而是 directed temporal entity graph 上的 temporal edge heterophily OOD problem**。这个定义之所以比“边时序方向模型”更强，是因为它把你的四个观察统一起来了：方向重要、时间外推差、未标注邻居极多、普通同类传播假设失效。THeGCN 已经开始讨论 temporal heterophily measurement；Dir-GNN 已经证明方向分离在异配图上有效；CaNet、TAR、DeCaf 已经说明图 OOD 需要环境、因果或重加权视角；但在加密货币实体级风险识别场景下，这几个点并没有被很好地合到一起。fileciteturn0file0 citeturn22view0turn21view0turn25view0turn25view2turn25view3

如果你能把论文主贡献写成下面这种形式，研究价值会明显高于“我提出了一个更强的 GNN”：

第一，提出并公开一个**真实、可复现、面向未来时间外推的比特币实体风险 benchmark**，证明随机分层结果会高估真实性能。第二，定义并测量这个场景里的**temporal edge heterophily**、未标注邻居稀释和方向性挑战。第三，提出一个**时间 OOD 稳健的方向感知图学习方法**，不是单纯多加层，而是显式把 feature-risk 机制与 flow-risk 机制分开，或者根据时间环境进行重加权。第四，说明一些类本质上更适合 ranking 或 subgraph reasoning，而不是单点闭集分类。这样的论文，不论最终更偏 benchmark 还是 method，都比单纯刷主协议分数更能形成“贡献”。citeturn20view0turn22view0turn21view0turn25view0turn25view2turn25view3

## 研究决策矩阵与晋级阈值

为了避免再次“先定路线再找证据”，更合理的做法是给每条路线设晋级门槛。这样最后的主线，是被实验筛出来的，而不是主观拍板定出来的。这个思路本身也符合最新 benchmark 与 re-evaluation 文献强调的严谨性。citeturn20view0turn24view0

对于“新基准与机制分析”路线，晋级门槛不应只是“协议好像合理”，而应是：协议、代码、split、baseline、评估脚本可以公开复现；定义出清楚的 challenge taxonomy，例如 benign / ambiguous / malignant 风险邻域、时间漂移强弱区间、方向性收益区间；并且至少能在一个额外公开数据资源上复现实验的一部分，哪怕任务不完全相同，也要证明结论具有迁移意义。只有这样，这条路才足以支撑顶会的数据/分析型贡献。citeturn24view3turn20view0turn21view4turn21view5

对于“时间 OOD 方法”路线，真正的晋级门槛应该更苛刻：不能只在 `class_balanced_khop` 上涨分。它必须在 `temporal_balanced` 上用 3-seed 证明稳定提升，并且最好在 conservative sensitive ranking 上也有提升；如果能进一步在外部数据或另一种时间任务上复现同方向结论，论文主线就会非常稳。用你当前结果做基线，更像样的门槛应当是 temporal Macro-F1 至少相对 EGS 再提升一个“论文看得见”的量级，而不是 1 个点以内的小波动。这个门槛之所以合理，是因为图 OOD 论文近年的主战场本来就是“在 distribution shift 下稳定提升”，而不是在 ID 上挤牙膏。fileciteturn0file0 citeturn25view0turn25view2turn25view3

对于“开放世界与风险发现”路线，晋级门槛应该是任务定义必须无歧义。你需要把“背景未标注”与“潜在未知类”严格区分开，并设计一个不会自我欺骗的 evaluation protocol；如果这一点做不到，这条路最好不要成为主线，只能作为补充分析。相反，如果你能构造 seen-class / novel-class / background 三者明确分离的测试协议，并证明模型对未来高风险实体的发现能力明显优于纯闭集分类，那么这条路会非常有现实价值。citeturn21view8turn10academia1turn10academia3

对于“子图与行为模式”路线，晋级标准应该围绕最难混淆对来设置，而不是围绕总体 Macro-F1。比如，若 motif 或 local flow 模型能显著减少 MIXER→EXCHANGE、GAMBLING→EXCHANGE 这类关键混淆，并且这类收益是节点分类模型无法替代的，那么它才值得被提升为主路线；否则，它更适合作为 case-study 驱动的补充发现。fileciteturn0file0 citeturn21view7

## 经过文献扫描后最值得优先投入的方向

在现在这个节点上，如果我必须给出**研究上限最高、同时又最贴合你当前资产**的优先建议，我不会选“纯 benchmark 路线”，也不会选“纯 open-world 路线”，而会选一个组合：**以时间 OOD 方法为主线，以 benchmark/机制分析为证据底座**。这个建议不是预设，而是基于你已经观察到的现象与近年论文版图之后的判断。fileciteturn0file0 citeturn20view0turn24view0turn25view0turn25view3

更具体地说，最值得投入的主问题可以被重述为：

**在大规模比特币实体交易图中，时间外推失败是否主要来自 temporal edge heterophily 与 environment-induced distribution shift；若是，能否通过方向感知、时间语义建模以及 feature-structure causal decoupling 学到更稳健的风险实体表示？** citeturn22view0turn21view0turn25view0turn25view3

这是比“继续加强 EGS”更高级的命题。它不是把你锁死在某个具体模型上，而是先固定科学问题，再允许多种候选解：一种可能是 EGS 加入 causal decoupling；另一种可能是时间环境重加权；还有一种可能是 temporal rewiring 或 heterophily-aware filtering。只要它们服务于同一个问题定义，论文就不会散。citeturn17academia0turn22view0turn25view2turn25view3

同时，我会把“新基准与机制分析”作为这条主线的**必要底座**，不是替代主线。原因是：异配、时间漂移和 directed edges 这些词，单写在方法标题里不会自动变成贡献；你需要用 benchmark 级的诊断去证明这真的是一个困难而且现实的问题。TGB 的成功很大程度上就来自“把问题定义出来并证明现有方法评得不对或学得不对”。你的项目已经具备朝这个方向延展的雏形。citeturn20view0turn17academia2turn24view0

## 最该先做的验证工作

真正下一步最重要的，不是立刻写一个名字更炫的新模型，而是做几组能决定候选路线生死的验证。第一组是**temporal edge heterophily 的量化**：把 THeGCN 的思路借来，为你的三套协议设计时间-方向-类别耦合的异配度量，检查 temporal split 中哪些类的邻域兼容矩阵、方向性统计和时间分布发生了系统迁移。只要你能把“为什么 temporal 崩”从故事变成量化图表，这篇论文的科学性就大幅提升。fileciteturn0file0 citeturn22view0turn23view6

第二组是**时间 OOD 的机制实验**：不要先比 10 个模型，而是围绕同一主假设做结构化对比，例如仅加时间环境重加权、仅做 feature/structure decoupling、仅做 temporal filtering、以及这些机制与方向聚合的组合。Graph OOD 文献已经说明，环境偏差、结构偏差与特征偏差不必然同步变化；你的数据又恰好是有时间的，因此这组实验的结论很可能比单纯再涨几分更有论文价值。citeturn25view0turn25view2turn25view3

第三组是**外部可认证性**。如果你想冲顶会，必须尽快决定是否能公开发布 benchmark 资产；若不能，至少要把方法的一部分迁移到公开资源上验证，比如 Elliptic++ 的 illicit address 任务，或者另一个可对齐的 temporal crypto graph 任务。反过来说，如果你能公开协议、代码和结果，并让别人直接复现实验，那 benchmark 线的价值会显著上升。citeturn21view6turn21view4turn21view5turn20view0

第四组是**节点分类边界的证据**。MIXER 和 EXCHANGE 的混淆现在已经是一个信号了：你应该正式检验“某些类是否需要 motif/subgraph reasoning”。如果局部流模式一旦引入就能显著降低关键混淆，那么这会给你提供一个很强的 secondary contribution；如果不能，也能反过来证明节点级时间 OOD 才是主矛盾。fileciteturn0file0 citeturn21view7

归根结底，**最有顶会潜力的方案不是盲目扩大模型空间，而是把你的现有发现整理成一个明确的问题定义：时间外推下的 directed temporal heterophily risk identification，并用 benchmark 级证据证明问题存在，再用 OOD/因果/方向感知的方法去解决它。** 这条路既没有被你前面的工程工作锁死，也最有机会把当前已有结果转化成真正有贡献的研究叙事。fileciteturn0file0 citeturn20view0turn21view0turn22view0turn25view0turn25view3
