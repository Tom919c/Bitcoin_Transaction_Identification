可以。结合你前面的目标、代码现状、两次研究报告、数据集特点和 10 月前结题这个时间限制，我建议你接下来不要再把项目做成“多模型对比”，而是明确转成一条研究主线：

# 最终推荐路线

## 面向低标签长尾场景的边属性-时间语义增强比特币交易图风险实体识别

英文可以暂定：

**Edge-Temporal-Aware Graph Learning for Long-Tailed Bitcoin Entity Risk Identification**

这条路线的核心不是“我又加了一个 GNN”，而是：

> 传统 GNN 在比特币交易图上效果不稳定，甚至可能被 MLP 反超。原因不是图没用，而是当前建模方式忽略了交易边语义、时间演化、类别长尾和异配邻居。
> 因此，我们构建一套边属性、时间信息、长尾类别和可解释子图联合考虑的风险实体识别框架。

这个故事最适合你现在的项目，因为你的项目文档里已经有 35 万节点、1700 多万边、2961 个有标签节点、19 维节点特征、6 维边特征，但当前边特征和时间信息没有真正进入模型；同时现有结果里 MLP 的 Macro-F1 反而高于 GraphSAGE，GAMBLING 类 F1 很低，这正好能成为研究动机。

# 一、先把项目科学问题定死

你接下来所有代码、实验、PPT、论文都围绕一个问题展开：

> 在标签极度稀疏、类别极度长尾、边交易语义丰富的比特币交易图中，为什么普通 GNN 不能稳定优于 MLP？
> 如果把交易金额、交易频率、时间演化和少数类结构纳入图学习过程，能否提升风险实体识别效果，尤其是 GAMBLING、BET、BRIDGE 等少数/敏感类别？

这比“基于 GNN 的比特币非法交易识别”强很多。

你原来的题目容易被老师问：

“交易所为什么非法？”
“INDIVIDUAL 为什么算非法？”
“NONE 是正常类吗？”
“你只是换了几个模型吗？”

新路线可以避开这些坑，把任务改成：

**比特币实体类型识别 + 风险类别分析。**

其中：

| 类型       | 类别                    |
| -------- | --------------------- |
| 中性/普通实体  | INDIVIDUAL, EXCHANGE  |
| 敏感/高风险实体 | BET, GAMBLING, BRIDGE |
| 未标注节点    | NONE，只作为图上下文，不作为正常类   |

这里一定要注意：**以后不要把 NONE 说成正常交易。NONE 是未标注节点。**

# 二、数据集选择策略：主数据集保留，不要推翻

你的主数据集不用换。它本身很适合这个方向。

你当前项目基于的大规模 BitcoinTemporalGraph 类数据集，原始论文介绍它包含 2.52 亿节点、7.85 亿边、约 6.7 亿笔交易，并且节点和边都有时间戳，提供实体类型标签和地址标签，这比很多传统 AML 数据集更适合做“实体级 + 边语义 + 时间泛化”的研究。([arXiv][1])

但是，数据集使用方式要升级。

不要只说：

> 我从大图里抽了 35 万个节点，然后跑 GNN。

要说成：

> 我们构建了三套数据协议，用于研究不同数据处理策略对比特币交易图风险识别的影响。

建议保留三套数据协议：

| 协议                   | 用途          | 内容                                           |
| -------------------- | ----------- | -------------------------------------------- |
| **Protocol A：复现协议**  | 对齐原始项目和已有论文 | TopK-ZScore + BRIDGE 邻居增强 + random split     |
| **Protocol B：推荐主协议** | 最终主结果       | 类别均衡 k-hop 子图 + 边金额/频率/时间特征 + temporal split |
| **Protocol C：消融协议**  | 证明每个改动有效    | 去掉边特征、去掉时间特征、去掉类别均衡采样分别比较                    |

这样你的数据处理本身就变成创新的一部分。

# 三、项目整体路线图

## 工作线 1：数据协议重构

这是最优先的。因为你现在最大的问题不是模型不够多，而是数据协议还不够研究化。

### 1.1 重新定义标签逻辑

当前配置里是 6 类：

```text
NONE / INDIVIDUAL / BET / GAMBLING / EXCHANGE / BRIDGE
```

后续代码建议改成：

```text
不参与 metric
```

这样更干净。

否则答辩时别人问“NONE 是正常用户吗”，会很麻烦。

---

### 1.2 改进子图采样

你现在的采样逻辑是：

```text
FinalScore = 0.3×Z(degree)
           + 0.2×Z(total_in)
           + 0.2×Z(total_out)
           + 0.3×Z(cluster_size)

selected = TopK(350000)
selected = selected ∪ BRIDGE_nodes ∪ BRIDGE_1hop_neighbors
```

这有两个问题：一是偏向高活跃节点，二是只增强 BRIDGE，容易让实验看起来偏向某一类。你的项目文档里也显示 BRIDGE F1 很高，但 GAMBLING F1 很低，这个现象和采样策略可能有关。

建议新增：

```text
class_balanced_khop
```

规则：

```text
1. 强制保留所有有标签节点；
2. 对 BET、GAMBLING、EXCHANGE、BRIDGE 统一做 k-hop 邻居扩展；
3. 对每个类别设置邻居采样上限；
4. 再补充一部分高 PageRank / 高交易额 / 高活跃背景节点；
5. 构建 induced subgraph。
```

最后你可以比较：

| 采样方式                      | 目的    |
| ------------------------- | ----- |
| TopK-ZScore               | 原始复现  |
| TopK + BRIDGE             | 当前方法  |
| Class-balanced k-hop      | 推荐方法  |
| Class-balanced + temporal | 最终主方法 |

这组实验非常适合写进报告。

---

### 1.3 金额和次数特征重做

金额类特征不能简单 Z-score，因为比特币交易金额通常是极长尾分布。

建议所有金额、次数类特征都改成：

```text
log1p
↓
clip 到 99% 或 99.5% 分位数
↓
robust scaling / z-score
```

边特征从原来的：

```text
reveal, last_seen, total, min_sent, max_sent, total_sent
```

扩展成：

```text
log_total_sent
log_min_sent
log_max_sent
avg_sent = total_sent / total
amount_range = max_sent - min_sent
duration = last_seen - reveal + 1
tx_frequency = total / duration
edge_recency = global_max_time - last_seen
```

这一步很关键，因为它把你的项目从“用了边特征”升级成“设计了交易语义特征”。

---

### 1.4 加 temporal split

随机划分可以保留，但不能作为最终主结果。

真实反洗钱/风险识别场景是：

```text
用过去识别未来
```

所以主实验必须有：

```text
Temporal Split:
train = 较早 60%
val   = 中间 20%
test  = 较晚 20%
```

更进一步，要避免未来信息泄漏：

```text
训练图只用训练时间之前的边
验证图只用验证时间之前的边
测试图只用测试时间之前的边
```

这一步很有研究味。因为 Elliptic 原始 AML 数据本身就是时间序列图，经典工作也强调用时间图做比特币 AML；而 Elliptic 的实验里 Random Forest 优于 GCN，也说明在这个领域“直接上 GNN”不一定自动赢，需要更细的数据协议和特征设计。([arXiv][2])

## 工作线 2：模型路线升级

你已经有了 MLP、GCN、GAT、GraphSAGE、APPNP、ResGraphSAGE。接下来不要再无脑加 GIN、ChebNet、GraphConv 这种普通模型。

你要加的是能服务研究问题的模型。

## 2.1 第一阶段模型：EdgeTransformer

你刚才重构版里已经开始做这个了。

核心是：

```text
x + edge_index + edge_attr → TransformerConv(edge_dim=...)
```

这个模型用于回答：

> 边交易语义是否能提升识别效果？

这是最直接、最容易解释、最适合答辩的创新点。

---

## 2.2 第二阶段模型：EdgeGatedSAGE

建议再实现一个你自己的轻量模型，不要只调用现成 `TransformerConv`。

可以设计成：

```text
message_j→i = gate_ij · W x_j

gate_ij = sigmoid(MLP([x_i, x_j, edge_attr_ij, time_attr_ij]))
```

含义很好讲：

> 不是所有邻居都同样重要。
> 对比特币交易图来说，高频、大额、近期、异常金额跨度的交易边应该传递更强的信息。

模型结构可以叫：

```text
EdgeGatedSAGE
```

或者：

```text
ET-GSAGE
```

这会比“我用了 PyG 的 TransformerConv”更像你自己的贡献。

---

## 2.3 第三阶段模型：方向感知

比特币交易是有方向的，发送方和接收方语义不同。

普通 `SAGEConv` 很容易把邻居当成无差别邻居。你可以做一个简单但有效的方向感知版本：

```text
h_in  = aggregate(in-neighbors)
h_out = aggregate(out-neighbors)
h_self = W_self x

h = MLP([h_self, h_in, h_out])
```

也就是说：

```text
输入资金邻居
输出资金邻居
自身特征
```

分开聚合。

这个创新点特别适合金融图，因为资金流方向本来就重要。

---

## 2.4 长尾类别优化

在模型基本跑通之后，再加长尾优化，不要一开始就加太复杂。

优先级：

```text
1. class-balanced focal loss
2. balanced softmax
3. minority prototype classifier
4. supervised contrastive loss
```

你现在 GAMBLING 样本很少，GraphSAGE 的 GAMBLING F1 很低；这部分可以作为一个明确实验目标：**提升少数风险类别识别能力**。

建议主指标不要只看 Macro-F1，还要加：

```text
Minority Macro-F1 = BET / GAMBLING / BRIDGE 的 F1 平均值
GAMBLING Recall
Precision@K for sensitive nodes
```

因为实际场景下，老师会更关心：

> 模型能不能把少数高风险节点找出来？

# 五、成功标准：你要追求什么结果？

不要只盯着 Weighted-F1。Weighted-F1 在类别不均衡时很容易被 INDIVIDUAL 主导。

你的主指标应该是：

```text
Macro-F1
Minority Macro-F1
GAMBLING Recall / F1
BET F1
BRIDGE F1
Precision@K for sensitive classes
```

我给你设三个层级的目标。

## 保底成功

即使最终模型没有大幅超过 MLP，只要你能证明：

```text
1. 普通 GNN 在该任务上确实不稳定；
2. 边属性和时间特征对少数风险类有贡献；
3. temporal split 下模型仍有一定泛化能力；
4. 可解释子图能辅助分析风险节点。
```

这个已经足够大创答辩讲得很漂亮。

## 良好成功

如果你做到：

```text
EdgeTemporal 模型 Macro-F1 比 GraphSAGE 提升 3–5 个点；
GAMBLING 或 EXCHANGE F1 明显提升；
Minority-F1 提升明显；
消融实验能说明 edge/time/sampling 都有贡献。
```

这就很有拿优秀结题/校级展示的潜力。

# 七、最终路线一句话版

你接下来的项目应该这样走：

> 先用现有结果证明普通 GNN 在比特币交易图上存在局限：MLP 甚至能超过 GraphSAGE，少数风险类别表现很差。然后从数据协议和模型机制两方面改进：构建类别均衡、时间无泄漏、边语义增强的数据处理流程；提出边属性和时间信息参与消息传递的 Edge-Temporal GNN；最后通过多基线、多消融、多随机种子和局部子图解释，证明该方法对风险实体尤其是长尾类别更有效。

这条路线最稳，因为它同时满足四件事：

```text
1. 能从你现有代码自然延伸；
2. 有明确研究问题；
3. 10 月前可落地；
4. 答辩时很好讲，也更像论文。
```

下一步最应该做的不是再讨论方向，而是直接开始 **v2 重构**：
**NONE 标签逻辑 + temporal split + class-balanced k-hop + log/clip 边时间特征工程**。这四个先落地，整个项目的地基就稳了。
