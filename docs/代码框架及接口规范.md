## 一、整体框架设计

项目将采用以下目录结构，每个模块都有明确的职责和对外接口：

```Plain
project/
├── config/                 # 配置文件
│   ├── default.yaml        # 默认配置
│   └── README.md           # 配置说明
├── data/                   # 数据处理模块（成员一、二）
│   ├── __init__.py
│   ├── build_graph.py      # 从数据库构建子图，生成data.pt
│   ├── features.py         # 特征工程（Z-score, 缺失值处理）
│   └── utils.py            # 数据库连接、节点筛选等工具
├── models/                 # 模型定义模块（成员三、四）
│   ├── __init__.py         # 统一暴露所有模型类
│   ├── base.py             # 可选的基类或接口规范
│   ├── mlp.py              # MLP模型
│   ├── gcn.py              # GCN模型
│   ├── gat.py              # GAT模型
│   ├── sage.py             # GraphSAGE模型
│   ├── res_sage.py         # 残差GraphSAGE
│   └── appnp.py            # APPNP模型
├── training/               # 训练与评估模块（成员三、四）
│   ├── __init__.py
│   ├── trainer.py          # 通用训练器（支持全图/mini-batch）
│   ├── evaluator.py        # 评估函数（宏F1等）
│   └── utils.py            # 学习率调度、早停等
├── interface/              # 可视化界面模块（成员五）
│   ├── __init__.py
│   ├── main_window.py      # PyQt主窗口
│   ├── data_loader.py      # 加载data.pt和模型
│   └── widgets/            # 表格、图表等子组件
├── experiments/            # 实验记录（可选）
│   └── logs/               # 训练日志、模型权重
├── scripts/                 # 便捷脚本
│   ├── run_preprocessing.py # 运行数据预处理
│   ├── train_model.py       # 启动训练
│   └── launch_interface.py  # 启动界面
├── requirements.txt        # 依赖库（固定版本）
├── README.md               # 项目说明
└── .gitignore              # Git忽略文件
```

## 二、模块接口规范

### 2.1 数据处理模块（负责成员一、二）

**核心产出**：一个统一的 `data.pt` 文件，包含以下键值对（使用 `torch.save` 保存）：

| 字段         | 类型                | 说明                                  |
| ------------ | ------------------- | ------------------------------------- |
| `x`          | `torch.FloatTensor` | 节点特征矩阵，形状 `[N, F]`，已标准化 |
| `edge_index` | `torch.LongTensor`  | 边索引，形状 `[2, E]`，COO格式        |
| `y`          | `torch.LongTensor`  | 节点标签，形状 `[N]`，整数编码（0-5） |
| `train_mask` | `torch.BoolTensor`  | 训练集掩码，形状 `[N]`                |
| `val_mask`   | `torch.BoolTensor`  | 验证集掩码，形状 `[N]`                |
| `test_mask`  | `torch.BoolTensor`  | 测试集掩码，形状 `[N]`                |

**接口设计**：

- `data/build_graph.py` 应提供一个函数 `build_and_save_data(output_path: str, config: dict)`，从数据库读取原始数据，执行节点筛选、特征工程、掩码划分，最终保存 `data.pt`。
- 其他模块（如训练）**只依赖** **`data.pt`** **文件路径**，不关心内部数据库细节。
  - 

**标签编码说明**：论文中采用整数编码。建议统一为：

```Python
label_map = {
    'NONE': 0,
    'INDIVIDUAL': 1,
    'BET': 2,
    'GAMBLING': 3,
    'EXCHANGE': 4,
    'BRIDGE': 5
}
```

### 2.4 可视化界面模块（成员五）

该模块独立于训练流程，通过加载 `data.pt` 和训练好的模型权重（`.pt` 文件）进行预测展示。建议设计以下接口：

## 三、配置文件规范

使用 YAML 格式，集中管理所有可配置项。默认配置文件 `config/default.yaml` 示例：

```YAML
data:
  raw_db: "postgresql://user:pass@localhost/bitcoin_db"  # 预处理阶段使用
  processed_data_path: "./data/processed/data.pt"        # 供训练使用
  num_classes: 6
  label_map: "config/label_map.json"                      # 标签映射文件

preprocessing:
  target_labels: ["INDIVIDUAL", "BET", "GAMBLING", "EXCHANGE", "BRIDGE"]
  zscore_params:  # 论文公式11-13
    c: 6
    alpha: 0.3
    beta: 0.2
    gamma: 0.2
    theta: 0.3
  max_nodes: 350000  # 目标子图规模

model:
  name: "ResGraphSAGE"  # 可选 mlp, gcn, gat, sage, res_sage, appnp
  params:
    hidden_channels: 256
    num_layers: 3
    dropout: 0.5
    # 其他特定参数（如GAT的heads）

train:
  seed: 42
  device: "cuda"
  epochs: 200
  lr: 0.01
  weight_decay: 5e-4
  batch_size: 1024   # 仅用于mini-batch训练
  neighbor_sizes: [25, 10]  # GraphSAGE采样邻居数
  early_stopping_patience: 50
  checkpoint_dir: "./experiments/checkpoints"
  log_dir: "./experiments/logs"

eval:
  macro_f1_average: "macro"  # 或其他选项
```

训练脚本 `scripts/train_model.py` 应接收配置文件路径作为参数，例如：

```Bash
python scripts/train_model.py --config config/default.yaml
```

## 四、团队协作建议

1. **Git 分支管理**：
   1. `main` 分支：稳定版本，仅包含已集成的代码。
   2. `dev` 分支：开发主线，各组员定期合并自己的分支。
   3. 每个成员基于 `dev` 创建自己的功能分支，如 `feature/preprocessing`, `feature/models`，完成后通过 Pull Request 合并。
      - 
2. **接口文档**：在 `README.md` 中明确各模块的接口约定，并在代码中使用类型注解和 docstring。
   1. 
3. **单元测试**：为每个模块编写简单的单元测试（例如在 `tests/` 目录下），验证接口是否满足预期。例如，测试模型 forward 能否正常输出正确形状的张量。
   1. 
4. **进度同步**：每日站会或每周例会，确保接口无偏差。
   1. 

## 五、总结

该框架将项目划分为**数据、模型、训练、界面**四大模块，模块间通过标准文件格式（`data.pt`）和清晰的类/函数签名解耦。每个成员可以在自己的模块内自由选择具体实现方式，只要保证接口兼容即可。配置文件统一管理所有参数，方便实验调参。
